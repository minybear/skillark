# 初始化项目文档骨架（init-project-docs）

为当前项目在 `docs/` 下建一套标准文档骨架。所有设计、计划、日志、issue 都按项目归档到 `docs/{项目}/` 下，不再平铺。

## 触发方式（两种，优先第一种）

1. **AI 自动识别（推荐）**：会话中判断出正在做某个项目（如 ioh 转移、websheet 认证），且 `docs/{项目}/` 不存在 → 主动列出将创建的目录给用户看，**询问确认后**再创建。
2. **用户直接指令**：用户说"在 docs 下给 XX 项目建目录" → 直接创建。

## 标准骨架

```
docs/{项目}/
    design/              # 规范：长期稳定，约束"怎么做"
        README.md        # 文档索引 + 状态（谁负责/是否最新）
    plan/                # 计划：随需求推进，记录"做什么/做到哪了"
        README.md
    logs/                # 开发日志：每个功能/修复完成后必写，按月归档
        README.md
    issues/              # 开发中发现的问题：带完整上下文，供冷启动
        README.md
        open/
        closed/
```

- `{项目}` 命名：小写、kebab-case，能一眼对应业务（如 `ioh`、`apple-esim-transfer`、`websheet-auth`）。
- 已存在的目录/文件**跳过，不覆盖**（幂等）。

## 工作流程

1. **识别项目名**：从当前任务/对话判断项目（如用户说"做 ioh 转移"，项目名 `ioh`）。判断不了 → 问用户项目名。
2. **检查现状**：`docs/{项目}/` 是否已存在、已包含哪些子目录。
3. **列出将创建的目录给用户看**（方案一的核心——先展示再确认）：

   ```
   我检测到当前在做「{项目}」，docs/{项目}/ 文档骨架还不完整。
   将为你创建以下目录与索引（已存在的会跳过）：

     docs/{项目}/design/README.md
     docs/{项目}/plan/README.md
     docs/{项目}/logs/README.md
     docs/{项目}/issues/README.md
     docs/{项目}/issues/open/
     docs/{项目}/issues/closed/

   是否创建？（可改项目名）
   ```
4. **确认后创建**：`mkdir -p` 各目录，写 4 个 README.md 索引（内容见下，已存在则跳过）。
5. 回复创建结果。

> 若用户是直接指令（方式 2），可跳过第 3 步询问，但仍要汇报创建了哪些。

## 各 README.md 索引内容

**design/README.md**：文档索引 + 状态表

```markdown
# {项目} · 设计规范索引
> 长期稳定的规范，约束"怎么做"。每份文档标注状态（最新/待更新/已废弃）。

| 文档 | 状态 | 负责人 |
|---|---|---|
| （按需添加：A-产品规范 / B-技术方案 / C-数据库设计 / D-测试标准 / F-详细设计/） | | |
```

**plan/README.md**：需求状态表

```markdown
# {项目} · 需求计划索引
> 单个需求一个目录：docs/{项目}/plan/{yyyyMMdd}-{模块}-{需求名}/。产出用 write-plan skill。

| 需求 | 模块 | 阶段 | 状态 |
|---|---|---|---|
| （暂无） | | | |
```

**logs/README.md**：日志归档规则 + 状态

```markdown
# {项目} · 开发日志索引
> 每个功能/修复完成后必写一条：docs/{项目}/logs/{yyyyMM}/{yyyyMMdd}-{模块}-{标题}.md。产出用 write-worklog skill。

| 月份 | 日志数 | 备注 |
|---|---|---|
| （暂无） | 0 | |
```

**issues/README.md**：open 状态表

```markdown
# {项目} · 问题索引
> 发现的问题写到 open/，修复后移 closed/ 并留一行指向 logs。产出用 write-issue skill。

| Issue | 优先级 | 模块 | 状态 | 登记日期 |
|---|---|---|---|---|
| （暂无） | | | | |
```

## 关键要求

- **先展示后创建**（方案一）：让用户看到将创建的完整目录清单并确认，不要默默创建。
- **幂等**：重复执行只补缺，不覆盖已有文件。
- **建完即提示**：骨架就绪后，提醒用户后续日志/issue/plan 分别用 `write-worklog` / `write-issue` / `write-plan` skill 归档。
