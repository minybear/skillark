# SkillArk v0.5 产品需求与推导

> 版本主题：AI 安装助手版（ArkPilot）  |  设计状态：Draft  |  基线：前一版本通过发布门禁

## 1. 不可约简的用户结果

**结果：** 规则无法解析的来源可由 AI 生成结构化候选或安装计划；用户看得懂、可修改，系统只执行通过 Schema 与策略验证的步骤。

该版本不以“新增页面”或“接入某个 API”为目标。只有当用户能够稳定获得上述结果，且失败不损坏既有 Skill、部署或凭据时，版本才成立。

## 2. 第一性原理推导

### 2.1 起点

- 用户拥有一个外部对象、风险对象、运行目标或版本环境。
- SkillArk 必须把它转化为可验证的内部状态，而不是直接相信来源描述。
- 任何不可逆操作都必须晚于解析、校验、计划与用户确认。
- 当前版本只引入完成结果所需的最小新状态和接口。

### 2.2 推导结论

1. **身份先于操作**：先明确对象是谁、来自哪里、版本是什么，再决定存储或执行。
2. **证据先于结论**：UI 展示的状态必须能追溯到文件、Hash、版本、规则或测试。
3. **失败默认不改变既有状态**：新增流程先落在临时区，成功验证后才提交。
4. **跨版本能力通过接口叠加**：不得绕开 v0.1 的 Skill/Agent/Workspace/Deployment 边界。
5. **概率能力不得拥有确定性副作用**：AI、相似度和风险评分只能影响建议，不能绕过策略。

## 4. MECE 范围

| 维度 | 本版本责任 | 非本版本责任 |
|---|---|---|
| 输入/来源 | 接收并识别本版本定义的输入 | 其他长尾输入留给后续版本或人工流程 |
| 解析/规范化 | 生成版本化内部对象和证据 | 不把无法解析字段编造成确定值 |
| 信任/策略 | 在进入写操作前给出允许、确认、阻断或未知 | 不承诺绝对安全或绝对兼容 |
| 存储/版本 | 保存不可变版本、来源、报告和状态 | 不以目标目录作为唯一真源 |
| 执行/分发 | 通过既有 Plan/Execute 或新增受控执行接口 | 不接受自由文本作为执行指令 |
| 观察/解释 | 展示真实路径、来源、差异、风险和结果 | 不隐藏部分失败或降级状态 |
| 恢复/退出 | 取消、失败清理、回滚、解除管理 | 不静默删除用户修改 |
| 治理/演进 | 版本化 Schema、接口和迁移 | 不提前冻结未经验证的公共 API |

## 5. 功能需求

### 5.1 核心模块

| 模块 | 职责 |
|---|---|
| ModelProviderPort | 统一 chat/structured output、超时、费用估算与取消。 |
| AIContextBuilder | 最小化发送内容，区分不可信文档与系统规则，执行脱敏。 |
| AIResolver | 输出 SkillCandidate、DependencyHints 或 InstallPlanDraft。 |
| SchemaValidator | 只接收版本化 JSON Schema，拒绝额外未知执行字段。 |
| PlanPolicyGate | 白名单可执行程序、参数规则、工作目录和网络/提权策略。 |
| SecretStore | 仅保存凭据引用，使用系统安全存储；模型看不到无关密钥。 |

### 5.2 核心流程

| 流程 | 步骤 |
|---|---|
| AI 解析来源 | 规则解析失败 → 用户选择 AI → 构建最小上下文 → 结构化输出 → Schema 校验 → 展示候选，不自动导入。 |
| 安装计划 | 文档/依赖提示 → AI 草案 → 确定性依赖探测 → 策略验证 → 用户确认 → 受控执行器。 |
| 降级 | 模型超时/费用超限/无 Key → 保存上下文与错误 → 回到手工定位或仅导入文件。 |

### 5.3 用户故事

- 作为多 Agent 用户，我可以完成“规则无法解析的来源可由 AI 生成结构化候选或安装计划；用户看得懂、可修改，系统只执行通过 Schema 与策略验证的步骤。”。
- 作为谨慎用户，我能看到决定依据，并在写入前取消。
- 作为高级用户，我能固定版本、查看原始证据并导出诊断。
- 作为离线或受限网络用户，我能看到明确降级状态，而不是得到伪成功。

## 6. 明确不做

- 无人值守全自动安装
- 静默管理员提权
- 平台代管 API Key
- AI 直接访问 Shell/文件写入

## 7. 可证伪版本假设

| 编号 | 可证伪结论 | 样本 | 指标 | 阈值 | 失败决策 |
|---|---|---|---|---|---|
| H-05-01 | AI 兜底能把非标准来源可导入率提高至少 30 个百分点。 | 100 个规则失败的真实页面/仓库，人工金标准。 | 正确候选率、人工修正时间。 | 正确率提升 ≥30pp，严重误定位 <2%。 | 未达标则 AI 只做解释，不生成导入候选。 |
| H-05-02 | Schema + Policy Gate 能阻断所有红队集中越权执行字段。 | 至少 300 个提示注入/恶意计划样本。 | 越权计划通过率。 | 0 个越权计划进入 Execute。 | 任一通过则停止执行功能，保留只读建议。 |
| H-05-03 | 至少 25% 的活跃内测用户愿意配置自带 Key 并重复使用。 | 邀请 100 名完成首次分发的用户。 | 配置率、7 日复用率。 | 配置率 ≥25%，复用率 ≥40%。 | 未达标则延后多 Provider，聚焦本地/免费模型或取消该卖点。 |

## 8. 验收条件

- 所有 H 假设达到阈值，或范围已按失败决策收缩。
- 关键写操作通过故障注入，无数据丢失与静默覆盖。
- 新增外部依赖存在超时、取消、限流/资源预算和降级策略。
- UI 能展示部分成功、未知和不完整状态。
- 数据迁移、备份与恢复在真实旧数据副本上验证。

## 9. 版本成功指标

- 首次完成该版本核心任务的成功率。
- 从开始到可验证结果的中位时间与 p95。
- 失败后既有状态保持完整的比例（目标 100%）。
- 用户需要绕过策略、手工修复或退出流程的比例。
- 该版本引入的支持工时与高优缺陷数量。
