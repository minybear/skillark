# SkillArk v0.2 测试与逆向验证计划

## 1. 逆向思维：该版本最可能如何失败

| 翻车方式 | 影响 | 设计防线 |
|---|---|---|
| 默认分支或标签被重写 | 同一 URL 得到不同内容 | 将 resolved commit 作为版本身份；分支仅是跟踪策略。 |
| 仓库过大或含大量无关文件 | 下载慢、磁盘爆炸 | 大小上限、超时、浅克隆/归档、取消与缓存配额。 |
| 子模块/LFS 内容缺失 | 导入后 Skill 不完整 | 识别并显式标记 unsupported，不静默忽略。 |
| 更新覆盖本地修改 | 用户资产丢失 | 原始版本不可变；更新创建新版本；部署修改先导回或解除管理。 |

## 2. 测试层级

### Unit

- 规范化、状态机、策略、Hash 和错误映射。
- 所有纯函数使用表驱动测试与性质测试。

### Contract

- 外部来源、模型、环境或扩展使用录制响应和契约样本。
- API 字段缺失、类型变化、分页漂移必须覆盖。

### Integration

- SQLite 迁移、缓存、文件系统、任务取消和恢复。
- 成功与失败的数据库/文件系统顺序组合。

### End-to-End

- 从 UI 输入到可验证结果、回滚和诊断。
- 离线、权限不足、部分成功、旧数据升级和多语言路径。

## 3. 故障注入矩阵

| 阶段 | 故障 | 预期 |
|---|---|---|
| 获取/解析 | 超时、限流、内容改变 | 保留旧状态，标 stale/failed，可重试 |
| 临时存储 | 磁盘满、权限不足 | 不提交业务记录，清理或登记临时项 |
| 数据库 | commit 失败 | 文件状态回滚或进入 recovery_required |
| 文件替换 | 重命名失败、目标被占用 | 原目标保持可用，不标成功 |
| 验证 | Hash/证据不一致 | 不提交成功，保留诊断 |
| 回滚 | 备份损坏 | 进入恢复中心，禁止静默继续 |
| 进程 | 强杀/系统重启 | 下次启动识别 Operation 并修复 |

## 4. 安全与隐私测试

- 路径穿越、Zip Slip、符号链接逃逸。
- Token/API Key/环境变量不进入日志、错误、遥测和诊断。
- 外部文本不能改变系统策略或获得未声明能力。
- 资源耗尽：超大文件、深层目录、压缩炸弹、无限分页。

## 5. 发布门禁

- 关键假设实验通过。
- P0/P1 自动化测试通过。
- 100 次关键流程故障注入无数据损坏。
- 真实升级副本完成备份、迁移、失败恢复。
- 文档与已知限制和实际支持矩阵一致。
