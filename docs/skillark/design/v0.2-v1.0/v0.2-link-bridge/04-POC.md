# SkillArk v0.2 POC 与证伪计划

## 1. POC 目标

实现 GitHub 公共仓库链接到 RepositoryLocator 的纯函数解析器，以及隔离下载、仓库扫描、更新 Diff 三段 POC。

POC 的目标不是证明方案正确，而是尽早找到会迫使架构或范围改变的证据。

## 2. POC 不做

- 不追求完整 UI。
- 不接入所有来源/Agent/平台。
- 不把手工样本测试替代自动化基准。
- 不因为已有代码投入而降低通过阈值。

## 3. 可证伪假设

| 编号 | 结论 | 样本 | 指标 | 通过阈值 | 失败决策 |
|---|---|---|---|---|---|
| H-02-01 | 规则解析能正确处理至少 95% 的公开 GitHub 仓库/子目录链接。 | 200 条去重真实链接，覆盖默认分支、tree/blob、尾斜杠、多个 Skill。 | 正确识别 remote/revision/subpath 的比例。 | ≥95%，且 0 次路径越界。 | 低于阈值则只支持明确格式，并把长尾留给 v0.5。 |
| H-02-02 | 更新前 Diff 不会让主要流程明显变慢。 | 30 名内测用户完成 3 次更新任务。 | 中位完成时间、跳过率、误更新率。 | 中位增加时间 <45 秒，误更新为 0。 | 若跳过率高则默认折叠 Diff，但高风险文件强制展示。 |
| H-02-03 | 缓存使重复导入 p95 时间降低至少 50%。 | 20 个 1MB-200MB 仓库，冷/热各 5 次。 | 导入 p95 与磁盘占用。 | 热缓存 p95 降低 ≥50%，缓存命中正确率 100%。 | 未达标则简化为归档缓存，取消复杂 Git object 复用。 |

## 4. 测试夹具

- `fixtures/valid/`：正常、最小、完整、多语言、大目录。
- `fixtures/invalid/`：缺字段、路径异常、损坏包、版本漂移。
- `fixtures/adversarial/`：越界、混淆、提示注入、资源耗尽、恶意扩展。
- `fixtures/failure-injection/`：断网、超时、数据库失败、文件替换失败、进程崩溃。
- `fixtures/golden/`：人工标注的期望输出和 Hash。

## 5. 实验输出

每个实验保存：

```text
experiment-id/
├── README.md
├── dataset-manifest.json
├── environment.json
├── raw-results.jsonl
├── summary.md
└── decision.md
```

`decision.md` 必须写明：通过、失败、部分通过，以及对范围/架构的实际修改。

## 6. 退出条件

- 所有关键 H 已得到可重复结果。
- 失败样本已转化为限制、错误码或明确不支持项。
- POC 代码中可复用部分有测试，试验性捷径未进入 Domain Core。
- 没有“后续再验证但先按当前方案开发”的高风险假设。
