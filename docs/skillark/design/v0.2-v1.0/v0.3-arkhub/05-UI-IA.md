# SkillArk v0.3 UI 与信息架构

## 1. 设计目标

UI 必须帮助用户回答五个问题：

1. 当前对象来自哪里、身份是否确定？
2. SkillArk 将做什么，真实路径/命令/版本是什么？
3. 已知风险、未知项和不完整证据是什么？
4. 哪些步骤成功、失败或被降级？
5. 用户下一步可以重试、修正、回滚还是退出？

## 2. 新增入口

- 新增 ArkHub 导航与统一搜索
- 来源状态/最近同步/离线标识
- 结果卡片显示原始来源、镜像与版本
- 来源筛选、许可证和更新时间筛选
- 缓存管理与手动同步

## 3. 页面状态（MECE）

| 状态 | 表现 | 允许操作 |
|---|---|---|
| empty | 未配置或无数据 | 创建、导入、查看示例 |
| loading | 有阶段和进度 | 取消、后台运行 |
| ready | 数据完整且可操作 | 计划、执行、查看详情 |
| partial | 部分来源/目标失败 | 查看失败、重试单项、继续成功项 |
| stale | 数据过期或上游未知 | 刷新、使用旧数据并确认 |
| incomplete | 扫描/解析未完成 | 不允许显示为安全/兼容通过 |
| blocked | 策略或前置条件阻断 | 查看证据、修复或高级覆盖 |
| recovery | 检测到未完成操作 | 进入恢复中心，不继续新写操作 |

## 4. 核心交互

### Plan 页面

- 显示对象身份、来源、版本和内容 Hash。
- 显示真实目标、将新增/修改/删除的内容。
- 警告按“必须处理”和“可接受风险”分组。
- 计划发生变化时，使旧确认失效。

### Result 页面

- 每个来源/目标/环境独立显示结果。
- 错误包含稳定错误码、阶段、证据和建议动作。
- 提供“重试失败项”，不重复执行成功项。
- 提供操作日志、诊断导出和回滚入口。

## 5. 可用性约束

- 不使用只有颜色区分的状态。
- 技术字段提供复制按钮和简短解释。
- 高风险确认要求展示影响，不使用泛化“确定吗”。
- 默认视图简洁；证据、原始 JSON 和日志可展开。
- 批量选择必须持续显示目标数量和影响范围。
