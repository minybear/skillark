# SkillArk v0.9 实施路线

## 1. 进入条件

- 前一版本发布门禁通过。
- 本版本事实/假设登记完成。
- POC 样本和基准脚本可运行。
- 数据迁移与回滚草案已评审。

## 2. Sprint 规划

### S1

迁移/备份/恢复演练

### S2

诊断、隐私和遥测

### S3

性能预算与大数据回归

### S4

Onboarding、文档、签名更新和 Beta 发布


## 3. 每个 Sprint 的固定交付

- 可运行代码与自动化测试。
- 更新后的事实/假设/未知登记。
- POC 或性能/安全证据。
- 数据迁移和恢复测试结果。
- 用户文档与已知限制。

## 4. 范围变更规则

- 新需求必须明确替换哪个同级目标，否则进入 Backlog。
- 任一关键假设失败时，优先缩小承诺，不靠增加更多自动化掩盖问题。
- P0 安全或数据完整性问题可以中断 Sprint；展示层优化不能。
- 没有证据的性能优化和抽象重构不进入版本关键路径。

## 5. 退出条件

- 核心用户结果可在受支持矩阵中重复完成。
- 可证伪阈值通过或范围按失败决策调整。
- 逆向测试无静默数据丢失、越权和伪成功。
- 运维、恢复、升级与诊断具备最小可用闭环。
