# SkillArk v0.2-v1.0 详细设计方法

> 状态：设计基线  |  核验日期：2026-07-30  |  适用范围：v0.2-v1.0

## 1. 目的

本设计包不是把既有产品经验机械复制到 SkillArk，而是对每个版本执行同一套可审计推导：

1. **第一性原理**：从不可再拆的用户结果、系统约束和风险边界推导方案。
2. **事实与假设分离**：事实必须有项目基线、官方规范、可重复实验或代码证据；假设必须进入验证清单。
3. **MECE 拆解**：功能范围按互斥且穷尽的维度拆分，避免重复建设与遗漏关键生命周期。
4. **逆向思维**：先写“该版本为什么会失败”，再设计保护、降级和回滚。
5. **可证伪原则**：每个关键结论都转为可执行实验，包含样本、指标、阈值、截止点和失败后的决策。

## 2. 证据等级

| 等级 | 定义 | 可作为设计事实 | 示例 |
|---|---|---:|---|
| E0 | 未验证观点或偏好 | 否 | “用户应该喜欢自动同步” |
| E1 | 单次人工观察 | 受限 | 某台电脑的 Agent 目录 |
| E2 | 可重复 POC 或测试 | 是 | 50 次故障注入均成功回滚 |
| E3 | 官方规范、稳定接口或项目基线 | 是 | Agent Skills 规范、Tauri 签名要求 |
| E4 | 多环境真实数据或持续指标 | 是 | 公开 Beta 的崩溃率与成功率 |

设计中的“事实”至少应达到 E2；外部平台能力优先使用 E3。无法达到时必须标注为假设或未知项。

## 3. 第一性原理推导模板

每个版本必须回答：

1. 用户最终要完成什么结果，而不是想点什么按钮？
2. 哪些约束不可违反：数据不丢失、路径不越界、凭据不泄露、AI 不拥有任意执行权等。
3. 若删除所有历史方案，完成该结果所需的最小状态、最小接口、最小流程是什么？
4. 哪些能力属于当前版本，哪些只是后续扩展点？
5. 哪个结论一旦被实验否定，版本范围或架构必须改变？

## 4. 事实、假设与未知项

统一标识：

- `F-版本-序号`：事实，例如 `F-02-01`。
- `A-版本-序号`：假设，必须有验证实验。
- `U-版本-序号`：未知项，必须指定负责人、验证时间点和决策影响。
- `H-版本-序号`：可证伪假设，必须有阈值和失败决策。

不得使用“业内通常”“应该没问题”“大概率”等模糊语句替代证据。

## 5. MECE 范围框架

每个版本按以下八个互斥维度检查范围：

1. **输入/来源**：数据从哪里来，身份如何追踪。
2. **解析/规范化**：如何变成 SkillArk 内部模型。
3. **信任/策略**：能否进入后续流程，需要什么确认。
4. **存储/版本**：保存哪些状态，如何更新、缓存和回滚。
5. **执行/分发**：实际改变了哪些文件或系统状态。
6. **观察/解释**：用户如何理解计划、结果、风险和差异。
7. **恢复/退出**：失败、取消、卸载和降级如何处理。
8. **治理/演进**：兼容、迁移、扩展与支持周期。

一个需求只能有一个主要归属；跨域影响以接口或非功能要求表达，避免重复实现。

## 6. 逆向设计模板

每个版本至少覆盖：

- 输入伪造或来源变化。
- 网络中断、超时、限流和部分成功。
- 数据库成功但文件系统失败，或相反。
- 用户手工修改受管目录。
- 版本升级、迁移与回滚失败。
- 性能在真实规模下失控。
- 安全扫描漏报、误报或被规避。
- AI 幻觉、结构化输出不合法或提示注入。
- 扩展崩溃、越权或供应链污染。

## 7. 可证伪实验格式

```text
H-xx-yy：明确的可失败结论
样本：固定语料、仓库、机器或用户任务
方法：可重复执行步骤
指标：成功率、p95 延迟、误报率、Hash 一致率等
通过阈值：进入开发或发布的最低标准
失败决策：缩减范围、改用替代架构、回退人工流程或终止功能
证据归档：测试报告、日志、基准脚本、样本清单
```

## 8. 跨版本不变量

1. 中央 Library 是受管 Skill 的主副本；目标目录不是隐式真源。
2. 所有写操作先 Plan 后 Execute，并落操作日志。
3. 原始版本、派生版本、部署快照分离。
4. AI 只能生成结构化建议，不可绕过策略层直接执行 Shell 或写文件。
5. 未受管目录不得静默覆盖；用户修改不得静默丢失。
6. 所有外部来源必须保留来源身份、版本或 Commit、内容 Hash。
7. 安全判断必须可解释；“未发现风险”不等于“绝对安全”。
8. 数据库迁移和更新发布必须先备份且具备恢复路径。

## 9. 参考依据

- **S1 SkillArk v0.1 设计基线**：项目内部基线：中央仓库、Agent Adapter、Workspace、Plan/Execute、Copy/Junction、操作审计。 参考：../skillark-design-kit/docs/
- **S2 Agent Skills Specification**：Agent Skill 的核心是包含 SKILL.md 的目录，可附带 scripts、references、assets 等资源。 参考：https://agentskills.io/specification
- **S3 GitHub REST API Documentation**：GitHub REST API 支持仓库内容、归档等接口；API 有版本与速率限制，认证可提高限额。 参考：https://docs.github.com/en/rest
- **S4 Tauri v2 Updater**：Tauri 更新包必须使用签名验证，更新公钥与私钥需要独立管理。 参考：https://v2.tauri.app/plugin/updater/
- **S5 Microsoft WSL Interop**：Windows 可通过 WSL interop 调用 Linux 命令并跨系统访问文件，但路径与文件系统语义不同。 参考：https://learn.microsoft.com/en-us/windows/dev-environment/wsl-interop
- **S6 skills.sh Documentation**：skills.sh 是开放 Agent Skills 目录和安装入口。 参考：https://www.skills.sh/docs
- **S7 ClawHub Repository**：ClawHub 是支持发布、版本和搜索文本型 Skill 的公开 Registry。 参考：https://github.com/openclaw/clawhub



# 各版本详细设计摘要


# v0.2 链接安装版（Link Bridge）

## 用户结果

用户粘贴 Git 仓库或子目录链接，能够预览候选 Skill、固定来源修订、导入、检查更新并安全回滚。

## 核心模块

| 模块 | 职责 |
|---|---|
| LinkResolver | 把输入规范化为 RepositoryLocator，不访问业务数据库。 |
| GitSourceAdapter | 获取 refs、归档或浅克隆，并返回不可变 SourceRevision。 |
| RepositoryScanner | 在受限目录内发现 SKILL.md，构建候选项和共享资源边界。 |
| RepositoryCache | 按 remote + revision 缓存，支持 LRU 与完整性校验。 |
| UpdateService | 比较已安装 revision 与远端 revision，生成更新计划。 |
| DiffService | 生成文本/文件树差异；二进制仅显示 Hash 与大小变化。 |

## 关键证伪假设

| 编号 | 结论 | 阈值 | 失败决策 |
|---|---|---|---|
| H-02-01 | 规则解析能正确处理至少 95% 的公开 GitHub 仓库/子目录链接。 | ≥95%，且 0 次路径越界。 | 低于阈值则只支持明确格式，并把长尾留给 v0.5。 |
| H-02-02 | 更新前 Diff 不会让主要流程明显变慢。 | 中位增加时间 <45 秒，误更新为 0。 | 若跳过率高则默认折叠 Diff，但高风险文件强制展示。 |
| H-02-03 | 缓存使重复导入 p95 时间降低至少 50%。 | 热缓存 p95 降低 ≥50%，缓存命中正确率 100%。 | 未达标则简化为归档缓存，取消复杂 Git object 复用。 |

## 主要翻车点

| 风险 | 影响 | 防线 |
|---|---|---|
| 默认分支或标签被重写 | 同一 URL 得到不同内容 | 将 resolved commit 作为版本身份；分支仅是跟踪策略。 |
| 仓库过大或含大量无关文件 | 下载慢、磁盘爆炸 | 大小上限、超时、浅克隆/归档、取消与缓存配额。 |
| 子模块/LFS 内容缺失 | 导入后 Skill 不完整 | 识别并显式标记 unsupported，不静默忽略。 |
| 更新覆盖本地修改 | 用户资产丢失 | 原始版本不可变；更新创建新版本；部署修改先导回或解除管理。 |

详细文档见 `v0.2-link-bridge/`。


# v0.3 多 Hub 聚合版（ArkHub）

## 用户结果

用户在一个搜索入口中查看多个来源的标准化结果，识别重复与原始来源，并按需缓存安装包。

## 核心模块

| 模块 | 职责 |
|---|---|
| ConnectorHost | 统一调度 Connector，隔离认证、分页、游标和速率限制。 |
| RegistryNormalizer | 把来源字段映射到最小公共模型，同时保留 raw_metadata。 |
| SyncScheduler | 按来源独立增量同步，支持游标、退避、中断恢复和手动刷新。 |
| SearchIndex | SQLite FTS5 + 结构化筛选，结果与来源状态解耦。 |
| DedupeEngine | 通过 canonical repository、content hash、fork relation 和相似度建立候选簇。 |
| CacheManager | 元数据、预览、包缓存三级存储与配额淘汰。 |

## 关键证伪假设

| 编号 | 结论 | 阈值 | 失败决策 |
|---|---|---|---|
| H-03-01 | 三个首批 Connector 的核心字段归一完整率 ≥90%。 | 完整率 ≥90%，错误映射 <2%。 | 不足字段保留来源专属展示，不进入统一筛选。 |
| H-03-02 | 统一搜索比逐站搜索降低任务时间至少 40%。 | 时间降低 ≥40%，正确率不下降。 | 若无明显收益，v0.3 收缩为来源收藏与快速跳转。 |
| H-03-03 | 10 万条元数据下常用查询 p95 <1 秒。 | 常用查询 p95 <1 秒，内存增量 <250MB。 | 改用增量 FTS/分页，取消高成本实时相似搜索。 |

## 主要翻车点

| 风险 | 影响 | 防线 |
|---|---|---|
| Hub API 改版或停服 | 同步全面失败 | Connector 版本探测、来源级熔断、保留 Git URL 降级。 |
| 字段归一丢失语义 | 错误比较或误导用户 | 公共字段 + raw metadata；不可映射字段不强行猜测。 |
| 去重误合并 | 隐藏真正不同的 Skill | 默认“候选重复簇”，不自动删除；展示差异证据。 |
| 索引和缓存无限增长 | 性能/磁盘失控 | 配额、LRU、保留策略、Vacuum 和按来源统计。 |

详细文档见 `v0.3-arkhub/`。


# v0.4 安全审计版（ArkGuard）

## 用户结果

用户安装或更新前得到文件级发现、权限清单、风险级别和明确的允许/确认/阻断决策。

## 核心模块

| 模块 | 职责 |
|---|---|
| PackageEnumerator | 以不跟随外部链接的方式构建完整文件清单。 |
| StaticScanner | 按文件类型调度 PowerShell/Bash/Python/Node/二进制扫描器。 |
| RuleEngine | 运行版本化规则，输出结构化 Finding，不直接给总分。 |
| PermissionInference | 从命令、路径和文档推断网络、文件、环境变量、提权等能力。 |
| RiskAggregator | 结合严重性、置信度、可达性和来源信任生成建议决策。 |
| TrustPolicyEngine | 把报告映射为 allow/confirm/block，并支持用户覆盖审计。 |

## 关键证伪假设

| 编号 | 结论 | 阈值 | 失败决策 |
|---|---|---|---|
| H-04-01 | 分层静态扫描能检出基准集中 ≥85% 的阻断级样本，误报率 ≤10%。 | Recall ≥85%，FPR ≤10%。 | 未达标则不自动 block，只提供 confirm + 证据。 |
| H-04-02 | 证据式报告使用户正确判断率高于单一风险分数。 | 正确率提升 ≥15%，时间增加 <60 秒。 | 若阅读成本过高，首屏摘要 + 展开证据。 |
| H-04-03 | 四级策略能覆盖 ≥95% 的用户决策，无需更多等级。 | 无需额外等级比例 ≥95%。 | 否则改为严重性与策略动作分离，不增加模糊等级。 |

## 主要翻车点

| 风险 | 影响 | 防线 |
|---|---|---|
| 误报过多 | 用户关闭安全功能 | 按证据展示置信度；规则可抑制；监控覆盖率与忽略率。 |
| 漏报导致虚假安全感 | 信任受损 | 明确“未发现”语义；分层扫描；不使用绿色“绝对安全”。 |
| 扫描器被大文件/压缩炸弹拖垮 | 拒绝服务 | 文件/总量/递归/时间预算；超限标记 incomplete。 |
| 规则更新改变历史结论 | 用户困惑 | 报告绑定 scanner/rule version；保留重扫历史。 |

详细文档见 `v0.4-arkguard/`。


# v0.5 AI 安装助手版（ArkPilot）

## 用户结果

规则无法解析的来源可由 AI 生成结构化候选或安装计划；用户看得懂、可修改，系统只执行通过 Schema 与策略验证的步骤。

## 核心模块

| 模块 | 职责 |
|---|---|
| ModelProviderPort | 统一 chat/structured output、超时、费用估算与取消。 |
| AIContextBuilder | 最小化发送内容，区分不可信文档与系统规则，执行脱敏。 |
| AIResolver | 输出 SkillCandidate、DependencyHints 或 InstallPlanDraft。 |
| SchemaValidator | 只接收版本化 JSON Schema，拒绝额外未知执行字段。 |
| PlanPolicyGate | 白名单可执行程序、参数规则、工作目录和网络/提权策略。 |
| SecretStore | 仅保存凭据引用，使用系统安全存储；模型看不到无关密钥。 |

## 关键证伪假设

| 编号 | 结论 | 阈值 | 失败决策 |
|---|---|---|---|
| H-05-01 | AI 兜底能把非标准来源可导入率提高至少 30 个百分点。 | 正确率提升 ≥30pp，严重误定位 <2%。 | 未达标则 AI 只做解释，不生成导入候选。 |
| H-05-02 | Schema + Policy Gate 能阻断所有红队集中越权执行字段。 | 0 个越权计划进入 Execute。 | 任一通过则停止执行功能，保留只读建议。 |
| H-05-03 | 至少 25% 的活跃内测用户愿意配置自带 Key 并重复使用。 | 配置率 ≥25%，复用率 ≥40%。 | 未达标则延后多 Provider，聚焦本地/免费模型或取消该卖点。 |

## 主要翻车点

| 风险 | 影响 | 防线 |
|---|---|---|
| 提示注入诱导危险步骤 | 生成恶意计划 | 不可信内容边界、无工具权限、白名单 Gate、ArkGuard 复扫。 |
| 模型幻觉依赖/路径 | 安装失败或污染环境 | 每一步必须可探测、可验证；未知命令默认拒绝。 |
| 密钥泄露 | 严重隐私事件 | 系统密钥库、日志脱敏、最小上下文、Provider 域名确认。 |
| 成本与延迟不可控 | 功能不可用 | 预算上限、token 估计、取消、缓存、无 AI 降级。 |

详细文档见 `v0.5-arkpilot/`。


# v0.6 兼容与可复现版（ArkCompat）

## 用户结果

分发前生成兼容报告；必要转换创建派生版本；项目通过 manifest/lockfile 在新机器恢复相同内容 Hash。

## 核心模块

| 模块 | 职责 |
|---|---|
| CapabilityRegistry | 保存 Agent/版本/平台的能力声明与证据来源。 |
| RequirementExtractor | 从 Skill 结构、指令和依赖提取要求，AI 只能提供提示。 |
| CompatibilityAnalyzer | Requirement × Capability → 状态、证据和修复选项。 |
| TransformationEngine | 执行版本化、可预览、可逆的声明式转换，输出 DerivedSkillVersion。 |
| ManifestService | 维护期望的 Skill、来源、目标和策略。 |
| LockfileResolver | 解析不可变 revision/hash，执行 restore/check/update/audit。 |

## 关键证伪假设

| 编号 | 结论 | 阈值 | 失败决策 |
|---|---|---|---|
| H-06-01 | Capability Profile 对测试矩阵中的失败原因预测 precision ≥90%。 | precision ≥90%，unknown ≤20%。 | 未达标则只显示确定性结构差异，不给百分比分数。 |
| H-06-02 | 声明式转换能解决至少 60% 的高频可修复不兼容。 | 通过率 ≥60%，严重语义回归 0。 | 否则限制为建议 Patch，不自动生成派生版本。 |
| H-06-03 | Lockfile 在干净环境恢复内容 Hash 一致率 100%。 | Hash 100%；失败均有明确缺失依赖。 | 任一静默不一致阻断发布。 |

## 主要翻车点

| 风险 | 影响 | 防线 |
|---|---|---|
| 兼容报告误判可用 | 用户认为已保证运行 | 显示证据与置信度；区分静态兼容和实测兼容。 |
| 转换改变语义 | Skill 行为偏离 | 限定声明式转换；保留 diff；不可安全转换则要求人工。 |
| Lockfile 不完整 | 换机仍失败 | 锁定来源、revision、subpath、Hash、转换版本和目标能力版本。 |
| CLI 与桌面规则分叉 | 结果不一致 | 共享 Domain Core 与 Application Services。 |

详细文档见 `v0.6-arkcompat/`。


# v0.7 多环境版（Multi-Environment）

## 用户结果

Windows、WSL 与 macOS 的 Agent 实例被独立发现、验证和分发，跨环境失败互不影响。

## 核心模块

| 模块 | 职责 |
|---|---|
| EnvironmentRegistry | 保存环境类型、身份、状态、能力和生命周期。 |
| EnvironmentAdapter | 统一命令、文件、路径、权限和原子替换接口。 |
| WSLAdapter | 枚举发行版，通过 wsl.exe 调用受控 helper，避免直接猜 Linux 语义。 |
| PathMapper | Windows、UNC、WSL 与 POSIX 路径的显式转换和验证。 |
| MacOSAdapter | 处理 POSIX 文件操作、Symlink、Keychain 和平台目录。 |
| CrossEnvironmentCoordinator | 为每个环境生成独立子计划，聚合但不共享事务。 |

## 关键证伪假设

| 编号 | 结论 | 阈值 | 失败决策 |
|---|---|---|---|
| H-07-01 | EnvironmentAdapter 可让 ≥80% 的部署服务代码保持平台无关。 | 核心服务平台条件分支 <20%。 | 否则缩小抽象，仅统一 Plan，不强求统一底层操作。 |
| H-07-02 | WSL 受控 helper 在支持矩阵中部署成功率 ≥98%。 | ≥98%，且 0 次写错发行版。 | 低于阈值则仅支持 WSL2 + 指定发行版。 |
| H-07-03 | macOS Beta 获得至少 50 名有效测试者且核心周活 ≥30%。 | ≥50 激活，周活 ≥30%。 | 不足则 v1.0 仅标注 macOS Preview。 |

## 主要翻车点

| 风险 | 影响 | 防线 |
|---|---|---|
| Windows 路径被错误映射到 WSL | 写错位置或数据损坏 | 不做字符串替换；通过目标环境 helper canonicalize。 |
| WSL 未运行或发行版删除 | 任务挂起 | 状态机、启动超时、明确 unavailable，不自动创建发行版。 |
| macOS 签名/权限问题 | 无法安装或更新 | 发布前独立签名/公证 Spike；失败则保持 Beta 手动安装。 |
| 跨环境事务假象 | 一个失败拖垮全部 | 子计划独立提交；UI 显示部分成功。 |

详细文档见 `v0.7-multi-environment/`。


# v0.8 扩展生态版（Ark Extensions）

## 用户结果

新的 Hub、Agent 和扫描规则通过受版本控制、受权限限制、可隔离的扩展接入。

## 核心模块

| 模块 | 职责 |
|---|---|
| ExtensionManager | 安装、启停、更新、版本解析与兼容检查。 |
| ExtensionHost | 独立进程运行扩展，限制环境变量、工作目录和生命周期。 |
| CapabilityBroker | 扩展只能通过声明能力调用网络、缓存、只读文件和日志。 |
| ManifestVerifier | 校验 manifest、包 Hash、签名、API 版本和权限。 |
| SDK Contracts | Connector/Agent/Rule 的版本化 JSON-RPC 合约与测试套件。 |
| CrashIsolation | 超时、心跳、资源限制、崩溃禁用与诊断。 |

## 关键证伪假设

| 编号 | 结论 | 阈值 | 失败决策 |
|---|---|---|---|
| H-08-01 | 进程外 Host 对搜索/发现类调用的额外 p95 延迟 <100ms。 | p95 <100ms，扩展崩溃不影响主进程。 | 若过慢，批量协议和长连接优化，不退回同进程原生。 |
| H-08-02 | SDK 发布后 8 周内至少产生 5 个可维护第三方扩展。 | ≥5 个，且单扩展平均支持 <4h/周。 | 不足则保持官方内部扩展，不建设市场。 |
| H-08-03 | 权限展示让测试用户对高权限扩展的误安装率下降 ≥50%。 | 下降 ≥50%。 | 否则增加默认禁用、分步授权和首次调用确认。 |

## 主要翻车点

| 风险 | 影响 | 防线 |
|---|---|---|
| 扩展越权读取项目/密钥 | 供应链事件 | 默认无文件/密钥权限；Broker 精确授权；主进程不传继承环境。 |
| 扩展 API 快速失控 | 维护成本爆炸 | 小接口、能力分层、实验 API 前缀、兼容测试。 |
| 恶意签名或私钥泄露 | 伪造官方扩展 | 密钥轮换/撤销列表；官方签名仅代表来源，不代表安全。 |
| 扩展拖慢搜索/扫描 | 主程序卡顿 | 超时、资源预算、异步调用、来源级熔断。 |

详细文档见 `v0.8-extensions/`。

# v1.0 稳定正式版（Stable）

## 用户结果

核心 Schema、Lockfile、扩展 API、支持矩阵和发布流程稳定；用户可预期升级、故障处理与安全响应。

## 核心模块

| 模块 | 职责 |
|---|---|
| CompatibilityContract | 冻结 Schema、Lockfile、Extension API 与迁移规则。 |
| SupportMatrix | 记录平台/Agent/版本/模式的 tested、supported、preview、unsupported。 |
| ReleaseTrain | RC、Stable、Hotfix、LTS 分支与签名发布自动化。 |
| SecurityResponse | 漏洞接收、分级、修复 SLA、撤销规则/扩展和公告。 |
| LifecycleManager | 版本支持窗口、弃用通知、迁移文档和兼容测试。 |
| ProductMetrics | 在隐私边界内验证价值、稳定性和支持负载。 |

## 关键证伪假设

| 编号 | 结论 | 阈值 | 失败决策 |
|---|---|---|---|
| H-10-01 | v1.0 RC 在四周内满足 crash-free sessions ≥99.5%，核心操作成功率 ≥99%。 | ≥99.5%/≥99%，无数据损坏。 | 不达标继续 RC，不发布 Stable。 |
| H-10-02 | 12 个月支持周期可在预计维护容量内完成。 | 维护占用 ≤总开发时间 40%，P0 按 SLA 清零。 | 超过则缩短矩阵或调整支持周期，不增加承诺。 |
| H-10-03 | Extension API v1 可实现三个不同类型扩展且无需私有逃生接口。 | 0 个未声明主程序接口依赖。 | 否则继续标 experimental，不冻结 v1。 |

## 主要翻车点

| 风险 | 影响 | 防线 |
|---|---|---|
| 过早冻结错误接口 | 长期技术债 | 只冻结已被真实实现和扩展使用的最小 API。 |
| 支持矩阵承诺过宽 | 维护失控 | supported 必须有 CI+真机+责任人；其他标 preview/unknown。 |
| 发布密钥/供应链受损 | 全量用户风险 | 离线备份、最小 CI 权限、双人恢复流程、制品证明。 |
| v1.0 被理解为“无缺陷” | 预期失衡 | 公开限制、已知问题、支持周期与安全模型。 |

详细文档见 `v1.0-stable/`。
