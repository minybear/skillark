# SkillArk v0.4 产品需求与推导

> 版本主题：安全审计版（ArkGuard）  |  设计状态：Draft  |  基线：前一版本通过发布门禁

## 1. 不可约简的用户结果

**结果：** 用户安装或更新前得到文件级发现、权限清单、风险级别和明确的允许/确认/阻断决策。

该版本不以“新增页面”或“接入某个 API”为目标。只有当用户能够稳定获得上述结果，且失败不损坏既有 Skill、部署或凭据时，版本才成立。

## 2. 第一性原理推导

### 2.1 起点

- 用户拥有一个外部对象、风险对象、运行目标或版本环境。
- SkillArk 必须把它转化为可验证的内部状态，而不是直接相信来源描述。
- 任何不可逆操作都必须晚于解析、校验、计划与用户确认。
- 当前版本只引入完成结果所需的最小新状态和接口。

### 2.2 推导结论

1. **身份先于操作**：先明确对象是谁、来自哪里、版本是什么，再决定存储或执行。
2. **证据先于结论**：UI 展示的状态必须能追溯到文件、Hash、版本、规则或测试。
3. **失败默认不改变既有状态**：新增流程先落在临时区，成功验证后才提交。
4. **跨版本能力通过接口叠加**：不得绕开 v0.1 的 Skill/Agent/Workspace/Deployment 边界。
5. **概率能力不得拥有确定性副作用**：AI、相似度和风险评分只能影响建议，不能绕过策略。

## 4. MECE 范围

| 维度 | 本版本责任 | 非本版本责任 |
|---|---|---|
| 输入/来源 | 接收并识别本版本定义的输入 | 其他长尾输入留给后续版本或人工流程 |
| 解析/规范化 | 生成版本化内部对象和证据 | 不把无法解析字段编造成确定值 |
| 信任/策略 | 在进入写操作前给出允许、确认、阻断或未知 | 不承诺绝对安全或绝对兼容 |
| 存储/版本 | 保存不可变版本、来源、报告和状态 | 不以目标目录作为唯一真源 |
| 执行/分发 | 通过既有 Plan/Execute 或新增受控执行接口 | 不接受自由文本作为执行指令 |
| 观察/解释 | 展示真实路径、来源、差异、风险和结果 | 不隐藏部分失败或降级状态 |
| 恢复/退出 | 取消、失败清理、回滚、解除管理 | 不静默删除用户修改 |
| 治理/演进 | 版本化 Schema、接口和迁移 | 不提前冻结未经验证的公共 API |

## 5. 功能需求

### 5.1 核心模块

| 模块 | 职责 |
|---|---|
| PackageEnumerator | 以不跟随外部链接的方式构建完整文件清单。 |
| StaticScanner | 按文件类型调度 PowerShell/Bash/Python/Node/二进制扫描器。 |
| RuleEngine | 运行版本化规则，输出结构化 Finding，不直接给总分。 |
| PermissionInference | 从命令、路径和文档推断网络、文件、环境变量、提权等能力。 |
| RiskAggregator | 结合严重性、置信度、可达性和来源信任生成建议决策。 |
| TrustPolicyEngine | 把报告映射为 allow/confirm/block，并支持用户覆盖审计。 |

### 5.2 核心流程

| 流程 | 步骤 |
|---|---|
| 安装前扫描 | 内容 Hash → 命中有效报告或重新扫描 → 规则发现 → 权限推断 → 风险聚合 → 策略决策。 |
| 更新重扫 | 新 Hash 使旧报告失效 → 对 Diff 文件优先扫描 → 输出新增/消失风险。 |
| 用户覆盖 | 阻断项显示证据 → 仅允许显式高级覆盖 → 记录原因、时间、版本和影响。 |

### 5.3 用户故事

- 作为多 Agent 用户，我可以完成“用户安装或更新前得到文件级发现、权限清单、风险级别和明确的允许/确认/阻断决策。”。
- 作为谨慎用户，我能看到决定依据，并在写入前取消。
- 作为高级用户，我能固定版本、查看原始证据并导出诊断。
- 作为离线或受限网络用户，我能看到明确降级状态，而不是得到伪成功。

## 6. 明确不做

- 动态沙箱执行
- 云端恶意样本服务
- 绝对安全保证
- 全自动修复脚本

## 7. 可证伪版本假设

| 编号 | 可证伪结论 | 样本 | 指标 | 阈值 | 失败决策 |
|---|---|---|---|---|---|
| H-04-01 | 分层静态扫描能检出基准集中 ≥85% 的阻断级样本，误报率 ≤10%。 | 人工标注的恶意/危险/正常 Skill 基准集，至少 500 包。 | 阻断级 recall、正常包 false positive rate。 | Recall ≥85%，FPR ≤10%。 | 未达标则不自动 block，只提供 confirm + 证据。 |
| H-04-02 | 证据式报告使用户正确判断率高于单一风险分数。 | A/B 测试：总分版 vs 文件证据版，30 名测试者。 | 正确决策率、阅读时间、信心评分。 | 正确率提升 ≥15%，时间增加 <60 秒。 | 若阅读成本过高，首屏摘要 + 展开证据。 |
| H-04-03 | 四级策略能覆盖 ≥95% 的用户决策，无需更多等级。 | 记录 200 次安装决策和用户覆盖原因。 | 需要自定义例外的比例。 | 无需额外等级比例 ≥95%。 | 否则改为严重性与策略动作分离，不增加模糊等级。 |

## 8. 验收条件

- 所有 H 假设达到阈值，或范围已按失败决策收缩。
- 关键写操作通过故障注入，无数据丢失与静默覆盖。
- 新增外部依赖存在超时、取消、限流/资源预算和降级策略。
- UI 能展示部分成功、未知和不完整状态。
- 数据迁移、备份与恢复在真实旧数据副本上验证。

## 9. 版本成功指标

- 首次完成该版本核心任务的成功率。
- 从开始到可验证结果的中位时间与 p95。
- 失败后既有状态保持完整的比例（目标 100%）。
- 用户需要绕过策略、手工修复或退出流程的比例。
- 该版本引入的支持工时与高优缺陷数量。
