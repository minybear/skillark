# SkillArk v0.4 POC 与证伪计划

## 1. POC 目标

建立安全基准集和无执行静态扫描流水线，先验证规则输出、资源预算和策略门，不先追求大而全规则库。

POC 的目标不是证明方案正确，而是尽早找到会迫使架构或范围改变的证据。

## 2. POC 不做

- 不追求完整 UI。
- 不接入所有来源/Agent/平台。
- 不把手工样本测试替代自动化基准。
- 不因为已有代码投入而降低通过阈值。

## 3. 可证伪假设

| 编号 | 结论 | 样本 | 指标 | 通过阈值 | 失败决策 |
|---|---|---|---|---|---|
| H-04-01 | 分层静态扫描能检出基准集中 ≥85% 的阻断级样本，误报率 ≤10%。 | 人工标注的恶意/危险/正常 Skill 基准集，至少 500 包。 | 阻断级 recall、正常包 false positive rate。 | Recall ≥85%，FPR ≤10%。 | 未达标则不自动 block，只提供 confirm + 证据。 |
| H-04-02 | 证据式报告使用户正确判断率高于单一风险分数。 | A/B 测试：总分版 vs 文件证据版，30 名测试者。 | 正确决策率、阅读时间、信心评分。 | 正确率提升 ≥15%，时间增加 <60 秒。 | 若阅读成本过高，首屏摘要 + 展开证据。 |
| H-04-03 | 四级策略能覆盖 ≥95% 的用户决策，无需更多等级。 | 记录 200 次安装决策和用户覆盖原因。 | 需要自定义例外的比例。 | 无需额外等级比例 ≥95%。 | 否则改为严重性与策略动作分离，不增加模糊等级。 |

## 4. 测试夹具

- `fixtures/valid/`：正常、最小、完整、多语言、大目录。
- `fixtures/invalid/`：缺字段、路径异常、损坏包、版本漂移。
- `fixtures/adversarial/`：越界、混淆、提示注入、资源耗尽、恶意扩展。
- `fixtures/failure-injection/`：断网、超时、数据库失败、文件替换失败、进程崩溃。
- `fixtures/golden/`：人工标注的期望输出和 Hash。

## 5. 实验输出

每个实验保存：

```text
experiment-id/
├── README.md
├── dataset-manifest.json
├── environment.json
├── raw-results.jsonl
├── summary.md
└── decision.md
```

`decision.md` 必须写明：通过、失败、部分通过，以及对范围/架构的实际修改。

## 6. 退出条件

- 所有关键 H 已得到可重复结果。
- 失败样本已转化为限制、错误码或明确不支持项。
- POC 代码中可复用部分有测试，试验性捷径未进入 Domain Core。
- 没有“后续再验证但先按当前方案开发”的高风险假设。
