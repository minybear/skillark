# 跨版本发布门禁

## 1. 设计门禁

- 事实、假设、未知项均有编号；关键假设有实验。
- MECE 范围检查无重复模块和无负责人空白项。
- 数据模型增量有迁移、备份、失败恢复设计。
- 新增外部依赖有超时、限流、认证、版本变化和降级策略。
- 新增写操作有 Plan、Execute、Verify、Rollback 四阶段。

## 2. 工程门禁

- P0 单元与集成测试通过。
- 故障注入覆盖关键状态转移。
- 数据库迁移在真实旧数据副本上通过。
- 路径含中文、空格、长路径和特殊字符的 Windows 回归通过。
- 敏感信息不进入日志、遥测、诊断包和崩溃报告。

## 3. 产品门禁

- 首次价值路径可被未参与开发的测试者独立完成。
- 错误信息提供下一步行动，不仅返回技术异常。
- 批量流程显示部分成功，不掩盖单项失败。
- 版本退出指标达到阈值；未达到时不得用“先发布再观察”绕过。

## 4. 发布与回滚门禁

- 发布包、更新包和元数据完成签名与校验。
- 升级前自动备份，迁移失败自动恢复。
- 前一稳定版本可重新安装；用户数据格式有明确兼容说明。
- Release Notes 包含已知问题、迁移影响和回滚步骤。
