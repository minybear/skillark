# SkillArk v0.7 产品需求与推导

> 版本主题：多环境版（Multi-Environment）  |  设计状态：Draft  |  基线：前一版本通过发布门禁

## 1. 不可约简的用户结果

**结果：** Windows、WSL 与 macOS 的 Agent 实例被独立发现、验证和分发，跨环境失败互不影响。

该版本不以“新增页面”或“接入某个 API”为目标。只有当用户能够稳定获得上述结果，且失败不损坏既有 Skill、部署或凭据时，版本才成立。

## 2. 第一性原理推导

### 2.1 起点

- 用户拥有一个外部对象、风险对象、运行目标或版本环境。
- SkillArk 必须把它转化为可验证的内部状态，而不是直接相信来源描述。
- 任何不可逆操作都必须晚于解析、校验、计划与用户确认。
- 当前版本只引入完成结果所需的最小新状态和接口。

### 2.2 推导结论

1. **身份先于操作**：先明确对象是谁、来自哪里、版本是什么，再决定存储或执行。
2. **证据先于结论**：UI 展示的状态必须能追溯到文件、Hash、版本、规则或测试。
3. **失败默认不改变既有状态**：新增流程先落在临时区，成功验证后才提交。
4. **跨版本能力通过接口叠加**：不得绕开 v0.1 的 Skill/Agent/Workspace/Deployment 边界。
5. **概率能力不得拥有确定性副作用**：AI、相似度和风险评分只能影响建议，不能绕过策略。

## 4. MECE 范围

| 维度 | 本版本责任 | 非本版本责任 |
|---|---|---|
| 输入/来源 | 接收并识别本版本定义的输入 | 其他长尾输入留给后续版本或人工流程 |
| 解析/规范化 | 生成版本化内部对象和证据 | 不把无法解析字段编造成确定值 |
| 信任/策略 | 在进入写操作前给出允许、确认、阻断或未知 | 不承诺绝对安全或绝对兼容 |
| 存储/版本 | 保存不可变版本、来源、报告和状态 | 不以目标目录作为唯一真源 |
| 执行/分发 | 通过既有 Plan/Execute 或新增受控执行接口 | 不接受自由文本作为执行指令 |
| 观察/解释 | 展示真实路径、来源、差异、风险和结果 | 不隐藏部分失败或降级状态 |
| 恢复/退出 | 取消、失败清理、回滚、解除管理 | 不静默删除用户修改 |
| 治理/演进 | 版本化 Schema、接口和迁移 | 不提前冻结未经验证的公共 API |

## 5. 功能需求

### 5.1 核心模块

| 模块 | 职责 |
|---|---|
| EnvironmentRegistry | 保存环境类型、身份、状态、能力和生命周期。 |
| EnvironmentAdapter | 统一命令、文件、路径、权限和原子替换接口。 |
| WSLAdapter | 枚举发行版，通过 wsl.exe 调用受控 helper，避免直接猜 Linux 语义。 |
| PathMapper | Windows、UNC、WSL 与 POSIX 路径的显式转换和验证。 |
| MacOSAdapter | 处理 POSIX 文件操作、Symlink、Keychain 和平台目录。 |
| CrossEnvironmentCoordinator | 为每个环境生成独立子计划，聚合但不共享事务。 |

### 5.2 核心流程

| 流程 | 步骤 |
|---|---|
| WSL 发现 | wsl --list → 查询发行版状态/版本 → 运行只读 helper → 返回 AgentCandidate。 |
| 跨环境分发 | 总计划拆为环境子计划 → 独立执行/验证 → 汇总部分成功 → 可单独重试。 |
| macOS 凭据 | 应用请求凭据引用 → Keychain 存取 → 日志只记录 reference id。 |

### 5.3 用户故事

- 作为多 Agent 用户，我可以完成“Windows、WSL 与 macOS 的 Agent 实例被独立发现、验证和分发，跨环境失败互不影响。”。
- 作为谨慎用户，我能看到决定依据，并在写入前取消。
- 作为高级用户，我能固定版本、查看原始证据并导出诊断。
- 作为离线或受限网络用户，我能看到明确降级状态，而不是得到伪成功。

## 6. 明确不做

- Linux 桌面正式版
- 远程服务器管理
- Dev Container 自动化
- 跨设备云同步

## 7. 可证伪版本假设

| 编号 | 可证伪结论 | 样本 | 指标 | 阈值 | 失败决策 |
|---|---|---|---|---|---|
| H-07-01 | EnvironmentAdapter 可让 ≥80% 的部署服务代码保持平台无关。 | 对 v0.1-v0.6 部署代码进行依赖扫描。 | 平台条件分支比例、重复代码。 | 核心服务平台条件分支 <20%。 | 否则缩小抽象，仅统一 Plan，不强求统一底层操作。 |
| H-07-02 | WSL 受控 helper 在支持矩阵中部署成功率 ≥98%。 | WSL1/2、Ubuntu/Debian、运行/停止、中文 Windows 路径。 | 安装/验证/卸载成功率。 | ≥98%，且 0 次写错发行版。 | 低于阈值则仅支持 WSL2 + 指定发行版。 |
| H-07-03 | macOS Beta 获得至少 50 名有效测试者且核心周活 ≥30%。 | 四周封闭测试。 | 激活、首次分发、周活和缺陷密度。 | ≥50 激活，周活 ≥30%。 | 不足则 v1.0 仅标注 macOS Preview。 |

## 8. 验收条件

- 所有 H 假设达到阈值，或范围已按失败决策收缩。
- 关键写操作通过故障注入，无数据丢失与静默覆盖。
- 新增外部依赖存在超时、取消、限流/资源预算和降级策略。
- UI 能展示部分成功、未知和不完整状态。
- 数据迁移、备份与恢复在真实旧数据副本上验证。

## 9. 版本成功指标

- 首次完成该版本核心任务的成功率。
- 从开始到可验证结果的中位时间与 p95。
- 失败后既有状态保持完整的比例（目标 100%）。
- 用户需要绕过策略、手工修复或退出流程的比例。
- 该版本引入的支持工时与高优缺陷数量。
