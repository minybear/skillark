# SkillArk v0.2-v1.0 产品需求文档

> 文档版本：1.0  |  状态：规划稿  |  基线：SkillArk v0.1

## 1. 文档目的

本文档定义 SkillArk 在 v0.1 本地 Skill Library 与多 Agent 分发能力完成后的产品路线，覆盖 v0.2 至 v1.0。它用于控制范围、安排开发优先级、明确验收口径，并保证各版本建立在统一架构边界上。

## 2. v0.1 基线

- Windows 本地优先。
- 本地目录与 ZIP 导入。
- Claude Code、Cursor、Codex、WorkBuddy 和自定义 Agent 探测。
- 全局与项目 Workspace。
- Copy/Junction 分发、验证、卸载和操作日志。
- 中央仓库是唯一受管源，写操作先 Plan 后 Execute。

## 3. v0.1 之后的产品战略

SkillArk 将沿着四条主线演进：

1. **来源统一**：从本地导入扩展到 Git 链接、多 Hub 聚合和私有来源。
2. **信任建立**：从“能安装”扩展到来源追踪、风险扫描、权限清单和策略阻断。
3. **跨 Agent 可用**：从目录复制扩展到能力分析、格式转换和项目环境复现。
4. **平台化维护**：从内置适配扩展到 WSL、macOS 和受控扩展 SDK。

长期定位：**聚合不同 Skill 来源，统一管理、审计、版本化，并安全分发到不同 AI Agent。**

## 5. v0.2 链接安装版（Link Bridge）

**版本目标：** 让用户从“只能导入本地文件”升级为“复制 Git 仓库或子目录链接即可安装”。

**用户价值：** 首次打通外部 Skill 来源与本地中央仓库，显著降低导入门槛。

### 核心范围
- 支持 GitHub 仓库、GitHub 子目录、任意 Git 地址导入。
- 自动扫描仓库内的 SKILL.md，并在一个仓库包含多个 Skill 时提供选择。
- 记录来源 URL、分支、Commit、子目录、内容 Hash 和许可证信息。
- 提供更新检查、版本 Diff、更新前备份和回滚。
- 加入浅克隆与仓库缓存，减少重复下载。
- 链接解析失败时给出可行动错误，而不是直接回退到自由命令执行。

### 核心用户故事
- 作为开发者，我粘贴一个 GitHub Skill 子目录链接后，可以预览并导入该 Skill。
- 作为已安装用户，我能看到上游是否更新，并在更新前查看文件差异。
- 作为谨慎用户，我可以固定在某个 Commit，避免自动追随不稳定分支。

### 发布验收
- [ ] 公开 GitHub 仓库及其子目录链接识别成功率达到 95% 以上。
- [ ] 包含多个 Skill 的仓库可以正确列出候选项，且不会把 README 误识别为 Skill。
- [ ] 更新失败时不破坏当前本地版本；可恢复到更新前版本。
- [ ] 来源元数据与实际安装内容可追溯到 Commit 和内容 Hash。

### 明确不做
- 多 Hub 搜索聚合
- AI 解析任意网页
- 自动执行依赖安装命令
- 私有 GitHub OAuth

### 数据模型增量
- sources、source_revisions、repository_cache、update_checks

## 6. v0.3 多 Hub 聚合版（ArkHub）

**版本目标：** 把分散在不同 Skill Hub 的内容统一到一个可搜索、可比较、可缓存的本地索引。

**用户价值：** 用户不再需要分别访问多个 Hub，SkillArk 开始具备“统一入口”的产品壁垒。

### 核心范围
- 定义 SkillSourceConnector 插件接口，来源接入与安装核心解耦。
- 首批接入 skills.sh、ClawHub 和 GitHub 搜索；保留自定义 Hub 配置入口。
- 建立本地 Registry 索引，支持关键词、来源、更新时间、许可证、兼容平台筛选。
- 支持元数据增量同步、热门包预缓存、其他包按需下载。
- 通过内容 Hash、上游仓库和相似度识别重复、镜像与 Fork。
- 提供缓存容量、过期策略、手动刷新和离线浏览。

### 核心用户故事
- 作为用户，我只需在 SkillArk 搜索一次，就能看到来自多个 Hub 的结果。
- 作为用户，我能区分原始仓库、镜像和二次修改版。
- 作为离线用户，我仍可浏览已同步的元数据和已缓存 Skill。

### 发布验收
- [ ] 新增 Hub 时无需修改部署引擎和 Agent Adapter。
- [ ] 索引同步支持中断恢复，不因单个来源失败阻塞其他来源。
- [ ] 10 万条元数据规模下，常用筛选和搜索响应小于 1 秒。
- [ ] 同一 Skill 的明显重复项能够合并展示并保留来源差异。

### 明确不做
- 完整公共商城
- 社区评论与付费
- 全量下载所有 Skill 包
- 企业账号体系

### 数据模型增量
- registry_sources、registry_items、registry_versions、cache_entries、sync_jobs

## 7. v0.4 安全审计版（ArkGuard）

**版本目标：** 让用户在安装前看清来源、权限、脚本和危险行为，建立“安全安装”心智。

**用户价值：** 把 SkillArk 从目录管理器升级为可信安装入口。

### 核心范围
- 扫描 PowerShell、Bash、Python、Node 脚本和可执行文件。
- 识别高风险命令、路径穿越、Zip Slip、符号链接逃逸、混淆内容和敏感目录访问。
- 生成权限清单：网络、项目文件、用户目录、环境变量、系统命令、软件安装等。
- 按低、中、高、阻断四级输出风险评分与解释。
- 校验包 Hash、来源 Commit、签名或校验和，并在内容变化后重新扫描。
- 支持策略：仅提示、需要确认、禁止安装；保留误报反馈。

### 核心用户故事
- 作为用户，我在安装前能看到该 Skill 可能访问哪些资源。
- 作为安全敏感用户，我能设置高风险 Skill 默认阻断。
- 作为开发者，我可以查看具体文件、行号和触发规则，而不是只看到一个分数。

### 发布验收
- [ ] 每个风险发现项必须包含文件、位置、规则、严重性和处理建议。
- [ ] 扫描引擎不执行被扫描脚本。
- [ ] 内容 Hash 变化后旧报告自动失效并重新生成。
- [ ] 阻断级发现未经明确覆盖不得进入安装执行阶段。

### 明确不做
- 云端恶意样本服务
- 动态沙箱执行
- 自动修复所有脚本
- 安全无风险保证

### 数据模型增量
- security_reports、security_findings、permission_manifests、trust_policies、scan_rules

## 8. v0.5 AI 安装助手版（ArkPilot）

**版本目标：** 使用 AI 处理非标准来源、复杂说明和依赖信息，但不让 AI 直接拥有任意执行权。

**用户价值：** 提升长尾来源解析能力，同时保持可解释、可确认、可回滚。

### 核心范围
- AI 作为规则解析失败后的兜底，识别网页、README 或非标准仓库中的 Skill 根目录。
- 从文档提取依赖、环境变量、安装步骤和注意事项，生成结构化 Install Plan。
- AI 对安全发现和兼容问题做自然语言解释。
- 支持用户自带模型 API Key；本地安全保存，不写入日志。
- 所有 AI 输出经过 JSON Schema 校验和确定性策略验证。
- 执行前逐步展示命令、工作目录、网络需求、权限和回滚方案。

### 核心用户故事
- 作为用户，我粘贴一个非标准 Skill 页面后，AI 能给出可确认的导入建议。
- 作为用户，我能看懂某条风险为什么危险，以及如何降低风险。
- 作为高级用户，我能修改 AI 计划，但执行器不会接受未验证的自由文本命令。

### 发布验收
- [ ] AI 无法直接调用 Shell 或文件写入接口。
- [ ] 结构化计划未通过 Schema 和策略校验时不得执行。
- [ ] 所有计划步骤均可预览、取消，并记录实际执行结果。
- [ ] 模型不可用时，核心导入、分发与安全功能仍可正常工作。

### 明确不做
- 全自动无人值守安装
- 静默管理员提权
- 平台代管用户密钥
- 承诺解析所有网页

### 数据模型增量
- ai_profiles、install_plans、install_plan_steps、ai_analysis_runs、secret_references

## 9. v0.6 兼容与可复现版（ArkCompat）

**版本目标：** 解决“目录能复制，但 Skill 在目标 Agent 中未必真正可用”的问题，并让项目 Skill 环境可复现。

**用户价值：** 建立跨 Agent 兼容层，让 Skill 分发从文件操作升级为运行能力管理。

### 核心范围
- 建立 Agent Capability Profile：支持格式、工具、Shell、路径、环境变量和约束。
- 输出每个 Agent 的兼容报告、缺失能力、可降级项和人工确认项。
- 支持 Frontmatter、路径、Shell 提示和 Agent 名称的可预览转换。
- 生成 skillark.json 与 skillark.lock，固定来源、Commit、Hash 和目标。
- 提供 CLI：restore、check、update、audit。
- 支持团队成员从 Lockfile 恢复相同项目 Skill 环境。

### 核心用户故事
- 作为多 Agent 用户，我能在分发前知道某个 Skill 在各 Agent 的兼容程度。
- 作为项目维护者，我能将 Skill 清单提交到 Git，其他成员一键恢复。
- 作为谨慎用户，我能预览转换差异并选择保留原始包。

### 发布验收
- [ ] 兼容报告必须区分“原生兼容、可转换、部分兼容、不兼容、未知”。
- [ ] 任何转换都生成派生版本，不覆盖原始 Skill。
- [ ] Lockfile 恢复结果与记录的内容 Hash 一致。
- [ ] CLI 与桌面端共享同一领域核心和数据库规则。

### 明确不做
- 保证所有 Agent 行为完全一致
- 自动修复任意业务逻辑
- 在线团队协作后台
- 远程执行环境

### 数据模型增量
- agent_capabilities、compatibility_reports、transformations、project_manifests、lockfile_entries

## 10. v0.7 多环境版（Multi-Environment）

**版本目标：** 从单一 Windows 本机扩展到 WSL 和 macOS Beta，统一管理同一设备上的多个运行环境。

**用户价值：** 覆盖真实开发者常见的 Windows + WSL、Mac 双环境工作流。

### 核心范围
- 自动发现 WSL 发行版及其中的 Agent、Skill 目录和可写状态。
- 支持 Windows 与 WSL 路径映射，通过 wsl.exe 执行受控 Linux 操作。
- 将同一 Agent 的 Windows、WSL、macOS 实例作为独立 AgentInstallation 管理。
- 发布 macOS Beta，支持 Copy、Symlink、Keychain 和基础自动更新。
- 提供环境标签、目标筛选和跨环境状态验证。
- 增加平台差异测试矩阵和数据迁移策略。

### 核心用户故事
- 作为 Windows + WSL 用户，我能分别把 Skill 分发到两个环境。
- 作为 Mac 用户，我能使用与 Windows 一致的 Library 和 Workspace 模型。
- 作为高级用户，我能明确看到每个 Agent 实例属于哪个环境。

### 发布验收
- [ ] WSL 操作不会误写入其他发行版或 Windows 同名路径。
- [ ] macOS Beta 覆盖 Intel 与 Apple Silicon 的核心安装流程。
- [ ] 跨环境部署失败互不影响，并能分别重试。
- [ ] 数据库迁移保持向后兼容，Windows 既有数据可直接升级。

### 明确不做
- Linux 桌面正式版
- 远程服务器管理
- Dev Container 全自动支持
- 跨设备云同步

### 数据模型增量
- environments、environment_paths、platform_capabilities、cross_env_operations

## 11. v0.8 扩展生态版（Ark Extensions）

**版本目标：** 让新增 Agent、Hub 和扫描规则不再依赖修改主程序，形成可维护的扩展机制。

**用户价值：** 降低生态变化带来的维护成本，为社区贡献和企业私有接入打基础。

### 核心范围
- 发布受限的 Connector SDK、Agent Adapter SDK 和 Security Rule SDK。
- 扩展包使用清单、版本、兼容范围、权限声明和签名。
- 扩展默认运行在受限能力范围内，不直接获取全部本地文件权限。
- 支持私有 Git 仓库、企业内部 HTTP Registry 和本地共享目录来源。
- 提供扩展启停、更新、兼容检查、崩溃隔离和诊断日志。
- 内置官方扩展目录，但暂不建设开放付费市场。

### 核心用户故事
- 作为开发者，我可以新增一个 Hub Connector，而不用 Fork SkillArk。
- 作为企业用户，我可以连接内部 Skill 仓库。
- 作为普通用户，我能看到扩展需要哪些权限并随时禁用。

### 发布验收
- [ ] 扩展 API 具备明确版本和兼容策略。
- [ ] 单个扩展崩溃不得导致主程序数据损坏。
- [ ] 未签名或高权限扩展需显著警告，企业策略可禁止安装。
- [ ] 官方核心功能不依赖第三方扩展才能完成基本流程。

### 明确不做
- 开放上传的公共扩展市场
- 付费结算
- 不受限制的原生插件
- 组织成员管理

### 数据模型增量
- extensions、extension_permissions、extension_installations、private_sources

## 12. v0.9 公开测试版（Public Beta）

**版本目标：** 冻结核心能力，集中解决稳定性、迁移、性能、安装体验和可观测性问题。

**用户价值：** 把“功能可用”提升为“普通用户敢用、出错可恢复、问题可定位”。

### 核心范围
- 完成 Windows 正式安装包、macOS Beta 安装包和安全自动更新。
- 建立数据库迁移、备份恢复、崩溃恢复和未完成操作修复。
- 提供诊断包导出，自动脱敏 Token、路径中的隐私信息和环境变量。
- 优化 500+ Skill、10 万索引数据和批量部署性能。
- 建立可选匿名遥测与崩溃报告，默认清晰告知并可完全关闭。
- 完成新手引导、用户文档、问题排查和升级说明。

### 核心用户故事
- 作为新用户，我能在十分钟内完成首次导入和多 Agent 分发。
- 作为遇到问题的用户，我能导出脱敏诊断包。
- 作为老用户，我升级后数据和部署状态不会丢失。

### 发布验收
- [ ] 阻断级缺陷清零，核心流程崩溃率达到发布门槛。
- [ ] 任一正式版本支持回滚到前一稳定版本。
- [ ] 升级前自动备份，迁移失败自动恢复。
- [ ] 文档覆盖安装、导入、分发、更新、安全、恢复和卸载。

### 明确不做
- 新增大型功能
- 公共 Skill 发布平台
- 商业订阅
- 跨设备实时同步

### 数据模型增量
- migration_history、diagnostic_exports、telemetry_preferences、crash_events

## 13. v1.0 稳定正式版（Stable）

**版本目标：** 形成可长期维护的稳定产品基线，完成 Windows 正式支持和 macOS 可用支持。

**用户价值：** SkillArk 成为多来源 Skill 管理、安全审计、跨 Agent 分发和项目复现的一站式工具。

### 核心范围
- 冻结核心数据模型、扩展 API 和 Lockfile v1 格式。
- 完成关键 Agent、Hub、Windows、WSL、macOS 的兼容矩阵。
- 稳定提供链接导入、聚合搜索、安全审计、AI 辅助、兼容分析和项目恢复。
- 建立 LTS 分支、版本支持周期、安全响应流程和发布节奏。
- 发布迁移指南、隐私政策、安全模型和扩展开发文档。
- 建立可量化的产品指标和用户反馈闭环。

### 核心用户故事
- 作为个人开发者，我可以从发现到安全安装再到多 Agent 分发全部在 SkillArk 完成。
- 作为项目维护者，我可以用 Lockfile 复现团队的 Skill 环境。
- 作为扩展作者，我可以依据稳定 API 接入新的 Agent 或 Hub。

### 发布验收
- [ ] 核心操作具备幂等性、审计记录和失败恢复。
- [ ] 正式支持矩阵中的 Agent 与平台通过自动化和真机回归。
- [ ] 安全模型、隐私边界和 AI 权限边界有公开文档。
- [ ] v1.0 发布后，兼容性破坏变更必须遵循语义化版本。

### 明确不做
- 大型 SaaS 后台
- 公共付费市场
- 组织级权限与结算
- 移动端

### 数据模型增量
- schema_v1_freeze、api_compatibility、support_lifecycle

## 14. 跨版本统一要求

### 14.1 架构边界
- Domain Core 不依赖 Tauri、具体 Hub、具体 Agent 或 AI 模型。
- SkillSourceConnector、AgentAdapter、DeploymentDriver、SecurityScanner 通过接口扩展。
- AI 只生成建议和结构化计划，确定性程序负责文件与命令执行。
- 原始 Skill、派生转换版本、部署快照必须分离存储。
- 所有写操作必须可审计、可取消、可恢复。

### 14.2 安全与隐私
- 默认最小权限，默认不执行 Skill 内脚本。
- Token、API Key 和私有仓库凭据使用系统安全存储。
- 日志与诊断包必须脱敏，不收集 Skill 正文和项目源码。
- 遥测必须可选、可关闭、可查看收集范围。
- 高风险操作需要展示实际路径、命令、权限和影响范围。

### 14.3 性能基线
- 500 个本地 Skill 列表加载小于 2 秒。
- 10 万条 Registry 元数据常用查询小于 1 秒。
- 100 个部署目标状态校验小于 5 秒。
- 大型 Hash、扫描、同步任务支持进度、取消和断点恢复。

### 14.4 兼容与迁移
- 数据库迁移前自动备份。
- Lockfile、扩展 API 和核心 Schema 在 v1.0 冻结。
- 不允许新版本静默覆盖用户手动修改的目标目录。
- Windows 路径包含中文、空格、长路径和特殊字符必须纳入回归。

## 15. 产品指标

### 北极星指标
**每周成功完成的受管 Skill 部署目标数。**

### 关键指标
- 首次价值时间：新用户从安装到首次成功分发的中位时间。
- 导入成功率：本地、Git 链接、Hub 包和 AI 兜底分别统计。
- 分发成功率：按 Agent、平台、Copy/Junction/Symlink 分类。
- 更新安全率：更新失败后成功恢复且无数据损坏的比例。
- 风险拦截率：被用户确认取消或策略阻断的高风险安装比例。
- 复现成功率：通过 Lockfile 在新环境恢复一致内容 Hash 的比例。
- 7 日留存：完成首次分发用户在 7 日内再次打开或操作的比例。

## 16. 发布门禁

每个版本进入发布候选前必须满足：

- P0 缺陷为 0，P1 缺陷有明确规避方案。
- 新增表与迁移脚本通过升级、降级或备份恢复验证。
- 核心写操作完成失败注入测试。
- 新增来源、Agent 或扩展完成超时、断网、权限不足和路径异常测试。
- 用户文档、变更日志和已知问题同步更新。

## 17. 主要风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| Hub 接口频繁变化 | Connector 失效 | 插件化、版本探测、降级到 Git/本地导入 |
| Agent 目录或格式变化 | 分发失败 | 可配置规则、能力档案、自动化兼容测试 |
| AI 生成错误计划 | 安全和稳定风险 | Schema 校验、策略引擎、人工确认、无自由执行权 |
| 安全扫描误报或漏报 | 用户不信任 | 可解释规则、误报反馈、多层扫描、不承诺绝对安全 |
| 一人开发范围失控 | 延期和质量下降 | 每版明确不做项，P0 优先，版本退出门禁 |
| Windows/WSL/macOS 差异 | 维护成本上升 | Environment 抽象、平台测试矩阵、分阶段支持 |

## 18. v1.0 之后候选方向

- v1.1：团队共享 Preset、私有 Hub、组织策略和审计导出。
- v1.2：可选跨设备同步与加密备份。
- v1.3：公共 Skill 发布、签名验证、作者身份与可信评分。
- v2.0：企业控制台、组织权限、策略下发和合规能力。

> v1.0 前不启动公共付费市场和大型 SaaS 后台，避免核心本地产品尚未稳定时过度扩张。
