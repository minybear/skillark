## 走过的弯路

1. **rustup shim 仍踩**：bash 下须把真实 toolchain bin 放 PATH 最前，否则 `cargo` 被当 rustup 子命令。
2. **git2 需要 cmake**：本机 cmake 不在 PATH，但 VS 2022 BuildTools 自带，加到 PATH 后编译通过；libgit2/​libssh2/​libz 全部源码编译（5m31s）。
3. **git2 Object 带生命周期**：v0.19 的 `git2::Object<'repo>`，`resolve_ref` 须显式 `'a`，否则 E0106。
4. **tokio 不是常规依赖**：link_bridge 用了 `tokio::spawn_blocking` 报错；改用 `tauri::async_runtime::spawn_blocking`（与 v0.1 一致）。
5. **`preview` 含 `view` 子串**：新增 Preview 按钮使既有测试 `/view/i` 匹配两处，改为 `/^view$/i` 精确匹配。
6. **locator move 进 fetch 闭包**：`spawn_blocking(move || fetch(&locator))` 后再用 locator 报 move 后借用；clone 一份进闭包解决。
7. **bash heredoc/中文 commit message 偶发 cwd 文件错误**：用 `-F <msgfile>` 提交规避。

## 经验 / 优化建议

1. **git2 构建依赖写进文档**：未来构建须 `cmake`（VS 自带路径）+ 真实 MSVC toolchain 上 PATH。建议加 `.cargo/config.toml` 或构建脚本固化。
2. **本地 git 夹具绕开公网**：网络受限环境下，git2 单测用本地 init+commit 仓库当 remote，完整覆盖克隆/切支/解析，不依赖 GitHub。真实公网拉取单列为 POC issue。
3. **服务端 token 化 preview**：不把临时 checkout 路径回传前端，符合 Plan→Execute 与最小暴露原则。
4. **迁移草案≠实现序列**：设计包 sql 用并行编号 0002~0010，与仓库实现序列（0001/0002/0003）不一致，落地须按实际序列重排。
5. **第二增量（L6）待办**：更新检查（UpdateService）+ Diff + LRU 缓存（repository_cache/update_checks 表）。
