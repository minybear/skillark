# 20260727 · M2 · v0.1 核心闭环（导入 + 分发 + 审计 + UI）

## 做了什么

落地 v0.1 的核心价值闭环：**导入一次 → 规划 → 多目标分发 → 验证 → 卸载，全程审计**。
对应 `plan/20260725-bootstrap-v0.1/03-开发计划.md` 的 Task 7–11 + Task 12 子集 + Task 13 备份切片。

### 后端（Rust，hexagonal 分层，全程单测）

1. **Domain 扩展**（`domain/deployment.rs`、`operation.rs`）
   - `DeploymentRecord`、`VerifyResult`、`DriftReason`；为 `InstallMode`/`ConflictKind`/`DeploymentStatus`/`OperationType`/`OperationStatus` 补 `as_str` + `FromStr`，便于 DB 字符串往返。
2. **Ports**（`ports/mod.rs`）
   - `DeploymentDriver` 补全为 `probe / install / verify / uninstall`；新增 `SkillSourceAdapter`、`TargetProbe`、`InstallRequest/Result`、`UninstallResult`。
3. **Adapters**
   - `adapters/filesystem`：`copy_tree`（与 `hash_directory` 同策略跳过 symlink/reparse，保证 `hash(copy)==hash(source)`）、`rename_atomic`、`force_remove_dir_all`（Windows 清只读）、tmp/backup 命名。
   - `adapters/sources`：`local_dir`（`SKILL.md` 解析 + 包一层目录容错）、`zip`（`enclosed_name` + `has_no_traversal` + 词法包含三重 Zip Slip 防护）。
   - `adapters/deployment/copy`：8 种冲突由 `application` 层分类；Copy 安装 = 补偿事务（tmp→hash 校验→备份→原子 rename→失败回滚），`install_inner` + 调用方兜底清 tmp，保证无半成品、失败旧目标可用。
   - `adapters/deployment/junction`：Windows junction，**改用 `mklink /J` 创建 + `rmdir` 删除**（见弯路），`get_target`/`exists` 走 junction crate 只读 API。
4. **Repositories**：`operation_repository`、`workspace_repository`（含固定 `global-default` 幂等）、`deployment_repository`（partial unique index 语义：`upsert_active` 先 retire 旧活动行）；`skill_repository` 扩 `find_by_canonical_name`/`set_current_version`/`find_version_by_hash`/`get_version`/`delete_skill`。
5. **Application 服务**：`state`（`AppState::setup` 建池跑迁移 + 建 vault + seed global workspace）、`import_skill`（内容寻址快照 + 版本去重）、`plan_deployment`（纯 `classify` + `build_plan`，内部解析 version）、`execute_deployment`（多目标部分成功 + Operation 审计）、`verify_deployment`（不落状态，ADR-011）、`uninstall_deployment`、`backup`（`VACUUM INTO` 快照）。
6. **Commands + 接线**：13 个新 `#[tauri::command]`（导入/列表/删除/plan/execute/verify/uninstall/operations/backup），`lib.rs` 用 `.setup()` 建 `AppState` 并 `.manage()`；DTO camelCase，`tests/contracts.rs` 仍绿。

## 走过的弯路

- **`junction` crate `create` 被 EDR 拒**：本机 `FSCTL_SET_REPARSE_POINT` 在 `cargo test` 进程下返回「拒绝访问」（ShellBot/EDR 按父进程拦截），但同一命令在交互式 shell 跑通。改用 `cmd /c mklink /J` 创建、`rmdir` 删除，`get_target`/`exists` 保留 crate 只读 API。两个 junction 创建测试标 `#[ignore]` 并写明原因（代码经交互式 shell 手工验证）。
- **Temp 目录是 AV 热点**：junction 创建 + fs 密集的 e2e 测试在 `C:\Users\vito\AppData\Local\Temp` 下并行跑时被 AV 拖慢/拒绝，导致 `--all-targets` 偶发超时失败（单跑 0.2s 过）。把 junction 与 e2e 测试的临时根迁到用户主目录（真实 vault 也在主目录下），消除 flaky。
- **`tokio` 不是直接依赖**：服务层用 `tokio::task::spawn_blocking` 编译失败（tokio 仅 dev-dep）。改用 `tauri::async_runtime::spawn_blocking`，零新依赖。
- **`VACUUM INTO` 要纯路径**：传 `sqlite:` URL 报 code 14 unable to open；改成纯文件路径 + 单引号转义。
- **关联型 trait 的 trait object**：`DeploymentDriver` 有关联 `type Error`，`Box<dyn DeploymentDriver>` 需写成 `Box<dyn DeploymentDriver<Error = DeploymentError>>`。
- **Tauri 2.11 `setup` 签名**：返回 `Result<(), Box<dyn std::error::Error>>`（无 Send+Sync），`map_err` 注解要精确匹配，否则 `?` 转换失败。
- **8 处 clippy `redundant_closure`**：仓库与 adapter 的 `map(|r| Self::row(r))` → `map(Self::row)`；另有 `map_clone`/`permissions_set_readonly_false`/`let_underscore_future` 等按提示修或加 `#[allow]`（带注释说明）。

## 经验 / 优化建议

1. **EDR 环境的测试策略**：reparse 类操作在受控进程下被拦是真实风险。后续应给 Driver 注入「create/delete link」的可替换闭包，让单测用 fake 注入绕过 EDR，同时保留真实 mklink/rmdir 调用；或把 junction 创建测试单独放 `tests/` 且默认 `#[ignore]`，CI 在干净环境跑 `--ignored`。
2. **测试临时根统一到主目录**：建议把 `unique_tmp` 风格的 helper 抽到 `support` 模块，默认基于 `~/.skillark-test-<pid>`，避免 Temp 的 AV 抖动反复咬人。
3. **服务层 `spawn_blocking` 统一走 `tauri::async_runtime`**：避免引入直接 tokio 依赖，也保证 CLI/服务端复用同一套代码时只换 runtime。
4. **Plan/Execute 内部解析 version**：让命令层只传 `skillVersionId + targets`，footgun 更少，前端更薄。
5. **junction 创建用 mklink 而非 crate 直调**：在锁定的企业环境更通用，代价是 verify 多一次进程调用（v0.1 POC 可接受）。
6. **遗留**：Workspaces 页面、首次启动向导、ZIP 导入的文件选择对话框（目前用路径输入，未接 `plugin-dialog`）、真机回归与安装包为后续（Task 12/13 余项与 Task 13 发布门禁）。
