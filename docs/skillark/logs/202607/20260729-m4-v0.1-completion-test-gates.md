## 走过的弯路

1. **rustup shim 被当成 cargo**：`~/.cargo/bin/cargo.exe` 是 rustup shim，bash 下 `cargo test --all-targets`
   报 `unexpected argument`（被当 rustup 子命令）。真实二进制在
   `~/.rustup/toolchains/stable-x86_64-pc-windows-msvc/bin/`，须把它放 PATH 最前。
2. **junction「EDR 拦截」真相**：控制实验证明——`cmd.exe /c mklink /J` 直接调用**成功**；
   同一段 mklink 逻辑编进 Rust 二进制（哪怕拷到主目录）运行**失败「拒绝访问」**。即 EDR 按
   **父进程链**拦截「编译产物派生 cmd 建 reparse」，cmd 作父进程则放行。不是代码 bug、不是路径问题。
3. **bash 转义吞反斜杠**：`cmd /c mklink "$TESTROOT\\link"` 里 `\\U`→`\U` 被 bash 转义吞，路径变 `\src`
   无效，误判为权限问题。须用纯 Windows 路径或 `MSYS_NO_PATHCONV`。
4. **前端默认语言是中文**：App 导航测试用英文 `getByRole(name:/library/)` 找不到——`useNavigation`
   默认 `lang="zh"`，按钮是「技能库」。测试断言要按默认 zh 词条写。
5. **sqlx 链式坑**：`query_as(...)` 不是 future，`fetch_one/fetch_all` 才是。`rt.block_on(query_as(...).fetch_one(&pool))`。
6. **npm run check 会 typecheck 测试文件**：`src/test/**` 在 tsconfig include 内，`noUnusedLocals` 严格，
   未用的 import/param 直接报错——测试代码也要过 tsc。
7. **多 cargo 任务争用**：release（全优化编译全部依赖）+ 全量 test 同时跑，rustc 单进程 36min+。
   应串行：先让重编译任务独占完成。

## 经验 / 优化建议

1. **Windows 工具链定位写进 README/CLAUDE.md**：真实 cargo 在 `.rustup/toolchains/<tc>/bin`，
   避免每个会话都踩 shim 坑。建议在项目根加 `.cargo/config.toml` 或 env 脚本固化 PATH。
2. **测试临时根统一在主目录**（`~/.skillark-*-test`）：Temp 是 AV/EDR 热点，主目录稳定。
   建议抽公共 `support` helper（dataset_e2e/perf/services 已各自复制了 unique_dir，应去重）。
3. **前端 mock 要覆盖页面全部 invoke**：导航测试漏 mock `get_agent_overrides` 导致 unhandled rejection。
   建议做一个共享 `installAppIPC` mock 工厂，覆盖所有页面用到的 command。
4. **数据集测试比固定 fixture 文件更可维护**：20 skill/1000 文件/21MB 运行时生成，不把大二进制提交进库。
   `test-fixtures/` 下 7/28 的手工中文 fixture 现已被 `windows_path_matrix` 测试取代，可考虑清理。
5. **junction 运行时降级**：建议首次 junction 安装遇「拒绝访问」时 UI 提示改 Copy 并记入 Operation
   （详见 G6 issue 后续项），把环境限制变成对用户友好的可恢复路径。
6. **遗留**：release 安装包全新安装/覆盖升级需真机或干净 VM 验证；OneDrive/跨盘/只读真机矩阵依赖
   物理设备；junction 在干净环境补跑 `--ignored`。这三项是仅剩的设备依赖发布风险。
