# 20260725 bootstrap 项目文档与设计归档初始化

## 1. 背景/问题现象

仓库只有简短 README 和 `skillark-design-kit-v0.1.zip`，尚无按项目归档的 `docs/skillark/` 骨架，也没有可供后续会话冷启动的需求计划、设计索引、日志和 issue。

本次目标是解压并梳理设计包，在不修改原始输入的前提下建立 SkillArk v0.1 的正式文档基线。

## 2. 方案/根因

按仓库的文档规范完成以下工作：

- 原样解压到 `skillark-design-kit/`。
- 将正式副本归档到 `docs/skillark/design/v0.1/`。
- 建立 design、plan、logs、issues 四类索引。
- 产出 v0.1 启动需求的 00～05 六份计划文档。
- 将跨文档契约冲突登记为高优先级 issue。
- 更新仓库 README，指向正式设计、计划和问题索引。

## 3. 走过的弯路

1. Windows PowerShell 默认文本编码导致首次读取中文 Skill 说明时出现乱码；改为显式 UTF-8 后恢复。
2. 首次使用 `Copy-Item -LiteralPath` 配合通配符时，通配符不会展开，只有设计包 README 被复制；随后改为先枚举明确文件，再逐个按字面路径复制，并增加“必须归档 16 个文件”的数量断言。

## 4. 效果

- 原始设计包解压出 16 个文件：9 份设计文档、3 个 JSON Schema、2 个 Rust 示例、1 个 SQL 和 1 个说明。
- 正式设计区归档 16 个文件，目录层级保持清晰。
- 新增 4 个项目索引、6 份启动计划、1 个高优先级 issue 和 1 份开发日志。
- 建立 M0～M4 五个里程碑和 24 条首批核心测试用例。
- 原始解压目录保留，正式归档可与来源进行 Hash 对比。

## 5. 经验沉淀

1. 设计包不能直接散落在仓库根目录；原始输入和正式文档基线应分开，既保留来源，也保证后续只从固定索引进入。
2. 跨文档字段差异必须在写 DTO、migration 和状态机前冻结，否则返工会同时扩散到前端、后端、数据库和测试。
3. Windows 自动化脚本必须显式处理 UTF-8 和字面路径，尤其是中文文件名、通配符与 PowerShell cmdlet 组合。

## 6. 优化建议

1. 阶段 0 增加自动化 Contract Test，让 Rust DTO 序列化结果直接接受 JSON Schema 校验。
2. 文档归档脚本应加入文件数和 SHA-256 校验，避免静默漏拷贝。
3. 在正式工程质量门禁中统一文本编码为 UTF-8，并加入中文/空格路径测试。
4. 设计冻结完成后更新 `design/README.md` 状态和负责人，关闭对应 issue 并写专项 worklog。
