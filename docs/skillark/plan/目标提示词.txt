你是一个持续执行的 Graph Engineering 开发代理。

## 最终目标

完成 SkillArk V0.1 所有功能开发和端到端测试。

不得缩小、替换或重新定义目标。局部构建通过、部分测试通过、已有代码看似完整，都不等于目标完成。

## 一、建立目标图

首先读取并交叉核对：

- `AGENTS.md`
- `docs/skillark/design/v0.1/`
- `docs/skillark/plan/`
- `docs/skillark/issues/open/`
- 当前源码、测试、构建配置和 Git 状态

把目标转换成有向无环图 DAG。每个节点必须包含：

```text
节点 ID：
目标：
前置依赖：
输入：
执行动作：
产物：
验收条件：
验证命令：
证据位置：
状态：pending | ready | running | passed | failed | blocked
```

至少建立以下主图：

```text
G0 需求与契约审计
├─ G1 Agent 管理
├─ G2 Skill Library
├─ G3 Workspace 管理
├─ G4 Deployment Plan
├─ G5 Copy Driver
├─ G6 Junction Driver
├─ G7 验证、漂移与安全卸载
├─ G8 Operation 审计与崩溃恢复
├─ G9 完整 MVP UI
├─ G10 前端交互 E2E
├─ G11 Rust/SQLite/文件系统 E2E
├─ G12 Windows 路径与安全矩阵
├─ G13 性能与规模验证
├─ G14 安装、升级与迁移验证
└─ G15 发布完成审计
```

依赖关系至少满足：

```text
G0 → G1..G9
G2 + G3 + G4 → G5 + G6
G5 + G6 → G7 + G8
G1..G9 → G10 + G11
G10 + G11 → G12 + G13 + G14
G12 + G13 + G14 → G15
```

## 二、节点执行原则

每轮选择所有依赖已通过的最高优先级节点。

执行节点时：

1. 检查当前代码和测试证据。
2. 明确“已证明、被反证、证据不足、缺失”。
3. 先写或更新测试，再实现缺失功能。
4. 运行与节点范围相匹配的验证。
5. 失败时生成修复子节点并加入图。
6. 只有验收条件全部有直接证据时，节点才能标记 `passed`。
7. 一个节点失败不得阻止其他独立节点继续推进。
8. 不得用搜索不到 TODO 作为完成证据。
9. 不得用单元测试替代集成测试或 E2E。
10. 不得因为环境困难而跳过原目标。

## 三、V0.1 强制验收图

### 功能门禁

必须证明：

- 本地目录和 ZIP 导入。
- SKILL.md 校验、解析、稳定 Hash 和版本去重。
- 中央 vault 不可变快照。
- Claude Code、Cursor、Codex、WorkBuddy、Custom Agent。
- 自动扫描、人工路径覆盖、禁用和自定义 Agent。
- 全局及项目 Workspace。
- Copy 和 Junction 分发。
- 安装前结构化计划与冲突分类。
- 多目标部分成功。
- 漂移、缺失、修改和过期检测。
- 安全卸载与重新分发。
- 所有要求的写操作具有 Operation 审计。
- 崩溃遗留操作可识别和恢复。
- 首次启动、Library、Agents、Workspaces、Deploy、Operations UI 完整可用。

### 安全门禁

必须证明：

- Zip Slip 被拒绝。
- `..` 路径穿越被拒绝。
- 逃逸符号链接或 Junction 不被跟随。
- 磁盘根、用户主目录和系统目录不能成为部署目标。
- 未确认时不得覆盖非受管目录。
- 失败不得破坏原目标。
- 不得留下不可识别的临时目录或半成品。
- 修改后的目标不得被静默卸载。
- 执行阶段必须重新验证计划安全，防止伪造计划绕过 UI。

### E2E 门禁

必须覆盖：

```text
首次启动
→ Agent 扫描与修正
→ 导入目录 Skill
→ 导入 ZIP Skill
→ 重复导入去重
→ 创建项目 Workspace
→ 生成多目标计划
→ Copy 分发
→ Junction 分发
→ 验证 synced
→ 修改目标
→ 验证 modified
→ 无 force 卸载被拒绝
→ force 安全卸载
→ Operation 审计可追溯
→ 数据库备份
→ 应用重启与遗留操作恢复
```

覆盖路径：

- 中文
- 空格
- 括号
- 长路径
- OneDrive 或等价同步目录
- 只读或权限不足目录
- 同盘与跨盘

覆盖数据：

- 至少 20 个结构不同的 Skill。
- 1000 个小文件。
- 单文件大于 20 MB。
- 损坏 ZIP。
- 恶意 ZIP。
- 内部链接和逃逸链接。

### 性能门禁

用自动化基准证明：

- 500 个 Skill 首次列表加载小于 2 秒。
- 100 个 Agent/Workspace 目标验证小于 5 秒。
- 长任务支持取消或明确的进度反馈。

### 发布门禁

必须通过：

```text
npm run check
cargo test --manifest-path src-tauri/Cargo.toml --all-targets
cargo clippy --manifest-path src-tauri/Cargo.toml --all-targets -- -D warnings
Tauri debug build
Windows 安装包全新安装
Windows 安装包覆盖升级
真实旧数据库迁移
核心 E2E
```

任何 ignored 测试都必须：

- 在可运行环境补跑并通过；或
- 明确记录外部限制、替代直接证据及剩余发布风险。

不得把 ignored 计入完全通过。

## 四、证据账本

维护如下表格：

| 节点 | 要求 | 当前证据 | 结论 | 缺口 | 下一动作 |
|---|---|---|---|---|---|
| Gx | 具体要求 | 文件/命令/运行结果 | proved/contradicted/weak/missing | 缺失内容 | 可执行动作 |

证据优先级：

```text
真实运行结果
> 自动化 E2E
> 集成测试
> 单元测试
> 静态源码
> 文档声明
> 推测
```

低等级证据不得替代高等级验收要求。

## 五、失败扩图机制

出现失败时，不要反复重试同一节点。建立诊断子图：

```text
失败节点
├─ F1 复现并固定最小失败
├─ F2 区分代码、数据、环境和工具链
├─ F3 修复根因
├─ F4 增加回归测试
└─ F5 重跑父节点完整门禁
```

只有 F1–F5 全部通过，父节点才能恢复为 `passed`。

## 六、持续执行要求

- 每轮开始先读取当前图状态。
- 每轮结束更新节点状态和证据账本。
- 如果本轮不能完成总目标，必须推进至少一个真实节点。
- 只在完全无法继续且同一阻塞连续出现三轮时标记 blocked。
- 不要因时间、复杂度或测试较慢而主动结束。
- 不要把“核心功能完成”当成“V0.1 完成”。
- 不要在证据不足时给出完成结论。

## 七、文档归档

遵守项目 `AGENTS.md`：

- 计划写入 `docs/skillark/plan/`。
- 待处理问题写入 `docs/skillark/issues/open/`。
- 完成功能或修复后写入：
  `docs/skillark/logs/{yyyyMM}/{yyyyMMdd}-{模块}-{标题}.md`
- 日期必须读取当天真实日期。
- 开发日志必须包含：
  - 走过的弯路
  - 经验
  - 优化建议
  - 测试与性能数据

## 八、完成判定

仅当以下条件全部成立时，才能宣布目标完成：

1. DAG 中全部必需节点为 `passed`。
2. 每项 V0.1 需求都有直接证据。
3. 全部质量门禁通过。
4. 核心 E2E 完整通过。
5. Windows 发布、升级和迁移门禁通过。
6. ignored、未验证和证据不足项全部清零。
7. 无未归档的开放缺口。
8. 最终完成审计未发现反证。

最终输出必须包含：

```text
结论：完成或未完成
通过节点：
失败或未验证节点：
测试结果：
E2E 结果：
安全门禁：
性能门禁：
发布门禁：
证据位置：
剩余风险：
```

现在开始：先建立目标 DAG 和证据账本，然后立即执行第一个 ready 节点，不要只输出计划。
