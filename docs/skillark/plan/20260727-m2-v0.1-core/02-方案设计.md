## 1. 分层落点（沿用现有 hexagonal 结构）

```text
commands  ──(async, tauri::State<AppState>)──▶  application services
application services ──▶ domain（纯）+ ports（trait）+ repositories
ports trait 实现于 adapters/（filesystem / deployment / sources）
repositories ──▶ sqlx SQLite（Pool 由 AppState 持有）
```

| 层 | 文件 | 作用 |

## 2. 关键设计决策

### 2.1 中央仓库（vault）与内容寻址

- vault 根：`~/.skillark/vault/`；DB：`~/.skillark/skillark.db`（`AppState` 启动时建池 + 跑迁移 + 幂等地写入固定 `global-default` Workspace）。
- 导入快照路径：`<vault>/<canonical_name>/<content_hash 前 12 位>/`，**不可变**。同一 skill + 同一 hash 的版本只存一份（按 `(skill_id, content_hash)` 唯一约束去重，命中则复用 `skill_version_id`）。
- `skills.library_path = <vault>/<canonical_name>`（身份）；`skill_versions.library_snapshot_path = <vault>/<canonical_name>/<hash12>`（快照）。
- `canonical_name` 取自 manifest.name，做文件名安全化（保留 `[A-Za-z0-9._-]`，其余转 `_`，空则 `skill`）。

### 2.2 冲突分类（DEPLOYMENT-POC §4）

`preflight(source, target)` 依序判定：

1. target 不存在 → `None`
2. target 是文件 → `FileConflict`
3. 不可写 → `PermissionDenied`
4. 查 `deployments` 表该 target_path 的活动记录：
   - 有记录 + target 当前 hash == `deployed_hash` → `ManagedSame`
   - 有记录 + target hash == Library 当前版本 hash（但 ≠ deployed_hash）→ `ManagedOutdated`
   - 有记录 + target hash ≠ deployed_hash → `ManagedModified`
5. 无记录但 target 含 `SKILL.md` → `UnmanagedSkill`
6. 无记录的普通目录 → `UnmanagedDirectory`

`requires_confirmation = 任一 target 的 conflict ∉ {None, ManagedSame}`。

### 2.3 Copy 安装 = 补偿式事务（DEPLOYMENT-POC §3 + ARCHITECTURE §7）

```
tmp   = target.with_extension("skillark-tmp-<op>")   # 同级临时目录
copy_dir(source → tmp)              # 不跟随外部链接；逃逸链跳过
assert hash(tmp) == expected_hash   # 不匹配 → 删 tmp，失败
if target.exists():
    backup = target + ".skillark-backup-<op>"
    rename(target → backup)
rename(tmp → target)                # 同卷原子
on ANY error: rm_rf(tmp); 若已备份则 rename(backup → target) 复原
成功后：删 backup，返回 deployed_hash
```

不变量：**失败后旧 target 必须保持可用或可识别**；重命名均要求同卷（POC 范围，跨卷显式报错）。

### 2.4 Junction 驱动（Windows）

- 用 `junction` crate 创建/读取/删除 NTFS junction（无需管理员，NTFS 同/跨卷均可指向）。
- `mklink /J` 等价语义；`verify` 读 junction 目标与 Library 快照路径比对。
- 非 Windows 编译为占位实现（返回 `JunctionUnsupported`），驱动单测 `#[cfg(windows)]` 守卫。

### 2.5 ZIP 导入 + Zip Slip

- 逐条目解压：对每个 entry name 调 `path_safety::has_no_traversal`，join 后再 `is_within(extract_root, joined.canonicalize())`；任一不满足 → 整体失败并清理。
- 拒绝绝对路径条目与盘符前缀（`C:\` / `/`）。

### 2.6 多目标执行 + 审计（Task 11）

- `execute(plan)`：先写 `operations`（status=`running`），逐 target 调对应 Driver `install`；**单 target 失败不影响其他**。
- 每个 target 成功 → 写/更新 `deployments`（status=`synced`, deployed_hash）；失败 → deployments 不落 synced，错误信息入 operation。
- 结束写 operation 结果（`succeeded` / `failed`，`result_json` 含每 target 状态）。
- 满足"部分成功可见 + 可重试失败项"。

### 2.7 验证与卸载（Task 10）

- `verify(deployment)`：Copy 看 target hash vs deployed_hash / Library 当前版本 hash；Junction 看链接目标。输出 `VerifyResult { status, drift }`，**不新增持久状态**（ADR-011）。
- `uninstall(deployment)`：Copy 模式若 target 被修改默认不删（返回需确认）；Junction 删链接不删源。成功 → deployment status=`uninstalled`。

## 3. 可测性

- `Clock` trait 注入时间；`#[tokio::test]` + `:memory:`/临时 DB + 临时 vault 跑仓库与服务集成测试（需在 dev-deps 补 `tokio`）。
- Driver 用真实临时目录测；故障注入通过"复制中途制造非法路径/损坏临时目录"模拟。
- 临时目录沿用现有 `unique_tmp` 风格（`std::env::temp_dir` + pid + nanos），不引 `tempfile` 以保持依赖精简。
- 跨语言 DTO 继续受 `tests/contracts.rs` 的 JSON Schema 约束。
