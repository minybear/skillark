# 需求分析

| 疑问 | 澄清结论 |
|---|---|
| NSIS 信任哪个来源？ | 仅信任 Tauri 官方 GitHub 仓库 `tauri-apps/binary-releases` 的 `nsis-3.11` 资产；拒绝第三方代理。 |
| Junction 失败后是否自动 Copy？ | 否。两种模式语义不同，必须展示原始失败，由用户显式触发 Copy 重试。 |
| Copy 重试作用于哪些目标？ | 仅作用于本次 Junction 执行失败的目标，成功目标不重复部署。 |
| 如何保留审计？ | Junction 失败 Operation 保持失败；Copy 重试创建新的计划和 Operation。 |
| 手工中文 fixture 是否仍是测试输入？ | 否。代码无引用；`windows_path_matrix_chinese_spaces_parens_long` 已在运行时生成中文、空格、括号和长路径数据。 |
| 路径矩阵是否都依赖物理设备？ | 否。跨盘可用额外卷/VHD，权限不足可用 ACL；OneDrive 需真实同步客户端，独立环境可用 VM 或第二台设备。 |
| 什么算本轮完成？ | 自动化全绿、降级交互有测试、fixture 和文档一致、NSIS 安装包产出并完成可在当前环境执行的安装验证；外部环境项必须明确列为未验证。 |
