# 方案设计

## Junction 降级

| 维度 | A：静默自动 Copy | B：失败后显式 Copy 重试 | C：仅展示说明 |
|---|---|---|---|
| 可恢复性 | 高 | 高 | 低 |
| 语义透明 | 低 | 高 | 高 |
| 审计完整性 | 中 | 高 | 高 |
| 误覆盖风险 | 较高 | 低 | 低 |

定稿：选择 B。保留 Junction 原始错误，UI 只对失败目标提供“改用 Copy 重试”；重试重新生成只读计划并执行，因此沿用既有冲突检查和 Operation 审计。

## NSIS 工具链

| 维度 | A：官方 Tauri GitHub | B：NSIS 上游 SourceForge | C：第三方代理 |
|---|---|---|---|
| 与当前 Tauri 下载契约一致 | 是 | 需人工适配 | 否 |
| 供应链边界 | Tauri 官方 | NSIS 官方 | 不明确 |
| 本轮选择 | 是 | 仅作来源追溯 | 否 |

定稿：选择 A。允许 GitHub 资产重定向；下载后记录 SHA-256。若当前网络仍不可达，只接受从该官方资产离线转交的原文件。

## 测试资产

| 维度 | A：保留手工 fixture | B：只保留运行时生成矩阵 |
|---|---|---|
| 可重复性 | 依赖仓库文件 | 测试自包含 |
| 覆盖范围 | 中文/空格/括号 | 中文/空格/括号/长路径 |
| 维护成本 | 两套数据 | 一套数据 |

定稿：选择 B，同时更新证据账本，避免继续引用已删除的 fixture。
