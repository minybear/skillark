# SkillArk v0.1 项目启动 · 需求分析

## 澄清表

| AI 提出的疑问 | 澄清结论 |
|---|---|
| v0.1 的首发平台是什么？ | 仅 Windows；macOS、Linux、WSL 不进入发布承诺。 |
| v0.1 支持哪些 Skill 来源？ | 本地目录和 ZIP。GitHub 仓库/子目录链接按 Roadmap 延后到 v0.2。 |
| 是否建设公共市场或在线 Hub？ | 否；v0.1 只验证本地中央 Library 与跨 Agent 分发。 |
| 应用是否执行 Skill 内脚本或 AI 生成命令？ | 默认不执行。写文件只由确定性程序按结构化计划完成。 |
| 默认分发模式是什么？ | Copy；Junction 是明确标记的高级选项。 |
| Agent 路径是否可以写死？ | 不可以。Adapter 只返回候选，用户配置具有最高优先级。 |
| 全局部署是否允许空 `workspaceId`？ | 推荐不允许；创建固定 Global Workspace，保持查询与 Schema 一致。正式结论在设计冻结时写入 ADR。 |
| Agent 的 JSON 字段使用 `kind` 还是 `agentType`？ | 推荐对外 JSON 统一 `agentType`；Rust 内部类型可使用 `kind`，通过显式序列化映射隔离。 |
| 是否保留 `synced_after_external_update` 状态？ | 推荐不作为持久状态；使用 `synced`，在验证报告中记录 Library 版本变化。 |
| SQLite 使用什么 Rust 库？ | 阶段 0 用小型 POC 对比；当前推荐 `sqlx` 的 SQLite + migrations，保留退回 `rusqlite` 的条件。 |
| 完整 UI 是否立即开工？ | 否。先完成设计冻结、Agent 探测 POC、导入与分发 POC。 |
| 谁是架构与产品文档负责人？ | 尚未指定；索引中暂记角色，项目负责人需在 M0 指定具体 owner。 |

## 用户与关键任务

核心用户是同时使用多个 AI 编码 Agent、在多个项目中重复安装 Skill 的 Windows 开发者。

关键任务按优先级排序：

1. 导入并检查一个 Skill。
2. 确认本机 Agent 与其真实目标路径。
3. 预览一次分发会写入、覆盖或备份哪些目录。
4. 安全分发到多个目标，并独立查看每个目标结果。
5. 判断目标是 synced、outdated、modified、missing 还是 failed。
6. 在不误删用户修改的前提下卸载或解除管理。

## 核心不变量

1. 中央 Library 是唯一受管源，Agent 目录不是主副本。
2. 安装必须先 Plan 后 Execute。
3. 非受管目录不得静默覆盖。
4. 失败操作不得破坏原目标。
5. 版本使用稳定目录 Hash，不依赖 mtime。
6. 用户手动 Agent 配置不得被自动扫描覆盖。
7. 删除 Deployment 记录不等于必然删除目标目录。
8. 所有删除与替换都必须先验证规范化路径位于允许的 Skill 根目录。
