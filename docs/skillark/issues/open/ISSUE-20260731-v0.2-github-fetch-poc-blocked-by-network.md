# ISSUE-20260731 · v0.2 真实 GitHub 拉取 POC 被网络环境阻塞

> 状态：open（待网络可达 GitHub 时补真实拉取 POC）
> 严重度：v0.2 发布风险（Git 拉取是 v0.2 命门；代码已用本地夹具证明逻辑正确）
> 关联节点：L2 GitSourceAdapter / L7 发布门禁

## 现象

v0.2 Link Bridge 的核心是 Git 拉取，但本机对 GitHub 出网不稳定：
- `git push` / `git ls-remote https://github.com/...` 反复超时或 SSL reset（同 NSIS issue 的网络环境）。
- 因此**真实 GitHub 仓库的拉取 POC 暂无法在本机验证**。

## 已具备的替代证据（满足「记录外部限制 + 替代直接证据」）

- **代码逻辑正确性**：`GitFetcher`（`adapters/sources/git.rs`）用 **本地 git 仓库夹具**（git2 init+commit 出来的本地 remote）完整验证：
  - 默认分支克隆 + HEAD SHA 解析（`fetches_default_branch_locally`）
  - 指定分支 checkout + 该分支 commit SHA（`fetches_specific_branch`）
  - resolve→fetch roundtrip（`resolver_then_fetch_roundtrip`）
- **git2 编译链已证**：git2 0.19 + libgit2(libssh2/libz) 在本机 MSVC 编译通过（cmake 取自 VS 2022 BuildTools）。
- git2 在 HTTPS 下用 libgit2 的 **Windows Schannel** TLS 后端，不依赖 OpenSSL。

## 剩余发布风险 / 待办

1. **真实 GitHub HTTPS 克隆**：待网络可达时，对一个公开小仓库（如 octocat/Hello-World）跑 `GitFetcher::fetch` 实测：
   - 默认分支 + 指定分支/tag + commit ref 各一次；
   - 大仓库 / 私有仓库 / 子模块标记 unsupported 的边界。
2. **超时与取消**：当前 `fetch` 无显式超时/取消（设计要求资源预算）。真实公网下若网络半通可能挂起；L6/L7 应加 `FetchOptions` 超时 + 可取消。
3. **浅克隆**：当前为全量克隆；浅克隆（depth=1）是 H-02-03 缓存的优化，随 L6 补。

